How DeepTap Works: The Mental Model

DeepTap is an autoclicker for Android that lets you record and replay taps and swipes on your phone screen, then run them automatically in loops. But DeepTap is smart: it can watch for things on screen and make decisions about what to do next—like closing a popup or tapping a button when it appears.

To understand DeepTap, you need to know four core ideas:

1. Script: Your Recorded Actions

A Script is a sequence of taps and swipes you record. Each action is saved with its exact screen position (coordinates). When you press Play, DeepTap repeats these actions over and over, as many times as you set the loop count. Think of it like a macro: tap here, swipe there, tap again.

  • Click: a tap at a specific position on screen
  • Sweep: a drag from one position to another
  • Loop count: how many times to run all the actions (≥1). Set to 0 to disable the script without deleting it.

Each script has a name and can hold many actions. You can create multiple scripts and switch between them.

2. Detector: Recognizing What's on Screen

A Detector is DeepTap's way of recognizing things that appear on your screen—like a popup or a close button. Instead of blindly tapping the same spot over and over, DeepTap can see what's there and react.

How does a detector work? It compares a small reference image (called a Template) against what's currently on your screen, looking within a specific area (the Region). If they match closely enough, DeepTap knows that thing is present. For example:

Example: You want DeepTap to close a popup. You crop a screenshot of the popup's close button (the ×), save that image as a template, and tell DeepTap where on the screen to look for it. Every time DeepTap scans the screen, it checks that region and compares the template. If it finds the × button, it knows a popup is open.

DeepTap seeds 4 editable sample detectors to learn from (SIMPLE Popup1, SIMPLE Popup2, ADVANCE Popup Close Button, ADVANCE Popup Gone), and you can create more of your own.

3. Process: Smart Decision-Making

A Process is a mini state machine that uses detectors to decide what to do. It's a sequence of IF-THEN rules. For example:

  • IF you detect a popup THEN click the target button THEN close any popup that appears THEN Continue the loop
  • IF no popup is found THEN Reset the loop counter and start over

Once every loop of your script — by default right before the loop's first action — DeepTap can run a process to check the screen and make a decision:

  • Continue: keep looping
  • Reset: start the loop count from 1 again
  • Stop: end playback

Processes are like recipes: you write down the steps, and DeepTap follows them every time.

4. Region + Template: Where to Look and What to Match

A Region is a rectangular area on your screen. A Template is a small screenshot (a PNG image) of what you're looking for. Together, they tell DeepTap: "Look inside this rectangle and compare what you see to this image."

Region Position (x, y) and size (width, height) of the area to scan
Template A reference image (PNG) of what you want to find

When DeepTap scans, it measures how well the template matches what's in that region—a score from 0% to 100%. If the score meets the detector's threshold (typically 90%), it's a match.

Important: Regions and templates are device-specific. If you move the app to a different phone, the coordinates may not work. You can copy scripts and processes between devices, but you'll need to recapture the templates on the new phone.

The Two Modes: Edit Mode and Play Mode

Mode 1: Edit Mode — Building Your Script

When you open DeepTap, you start in Edit mode. This is where you:

  • Create and name scripts
  • Record clicks and swipes by tapping a floating toolbar button
  • Preview your actions on screen (with clickable handles and knobs)
  • Set the loop count and time limits
  • Attach a process to run once every loop, at its start or at its end (like "tap a button when it appears then close a popup")

The app stays in the foreground, and you see a floating toolbar with buttons to add actions, view your script, and start playing.

Mode 2: Play Mode — Autoclicking in the Background

When you press ▶ START on a script, DeepTap switches to Play mode:

  1. The DeepTap app slides to the background (you can see the app you're automating)
  2. The floating toolbar stays on top, now showing Play/Stop and a live log of what DeepTap is doing
  3. DeepTap executes the script actions in a loop, scanning the screen between loops to check for detectors
  4. If a detector matches, the attached process runs (e.g., close a popup, tap a button when it appears)
  5. Press ⏹ STOP to end playback and return to edit mode
You can always see what DeepTap is doing: the strip on the toolbar has two lines. Line 1 is the progress, e.g. L6/10 A4 · 12s (loop 6 of 10, action 4, 12 seconds). Line 2 is the newest message: process steps, detector hits, errors and why playback stopped. Process and detector messages appear there only while LIVE LOG is on (CONFIG → Advance). For the full step-by-step record, open Log detail in the toolbar menu — DETAIL LOG is on by default. If something goes wrong, these logs are the first place to look.

A Typical Setup Flow

Here's how you'd set up DeepTap for the first time:

  1. Create a script: Tap HOME → + NEW
  2. Record actions: Tap Add Click or Add Sweep on the floating toolbar. Tap/drag on the target app's screen to place the action. Repeat until you've recorded a full "cycle" (e.g., tap a button 5 times).
  3. Set loop count: Tap ⚙ View Script → scroll to LOOP COUNT → enter how many times to repeat (e.g., 10).
  4. Create a detector (optional): Tap DETECTORS → + NEW. Crop a screenshot of something you want to recognize (like a popup button). Save it as a template.
  5. Create or pick a process: Tap PROCESSES → pick an existing one or create new rules (e.g., "If popup appears, tap the target button, then close the popup").
  6. Attach the process: Go HOME → tap the script's ⋮ menu → Edit post-loop → toggle ON, choose Run at (Loop start or Loop end) and pick your process.
  7. Test: Press ▶ START and watch the live log. Let it run a few loops. Press ⏹ STOP.
  8. Refine: If actions are in the wrong spot, tap ⚙ View Script to edit each action's coordinates. If a detector isn't matching, go DETECTORS and adjust the region or template.
Pro tip: Try adjusting SCAN INTERVAL (ms) and CLICK DELAY (ms) in CONFIG → Advance → TIMING (tap SHOW) if detections or taps aren't reliable. When debugging, open Log detail from the toolbar menu for a readable step-by-step engine trace (DETAIL LOG is on by default).

Scripts: Create and Manage Automation Sequences

A script is a list of taps and sweeps that DeepTap records and plays back on your phone. DeepTap keeps all your scripts together in one library so you can switch between them, modify them, and run them whenever you need.

The Script List (Home Screen)

When you open DeepTap, you see the script list. Each row shows one script with all the information you need:

  • Script name — tap the name to make it your active script (or use the menu).
  • Metadata — N actions · loop N, followed in amber by ⟳ process name when a post-loop process is on.
  • Play button — tap ▶ to make the script active and open the floating toolbar. DeepTap moves itself to the background so you can see the app you are automating; press Play on the toolbar to run.
  • Menu button — tap ⋮ (three dots) to rename, duplicate, delete, or edit post-loop settings for this script.

Tip: A row highlighted with a cyan border and the ● ACTIVE badge is the active script — the one the toolbar plays. You can have many scripts, but only one active at a time.

The newest script is at the top of the list. In builds with a sync server and PRO MODE on, each card also shows the script's version after its name and the buttons ↑ UPLOAD, ↓ DOWNLOAD and CHECK, with ↑ UPLOAD ALL · ↓ DOWNLOAD ALL · CHECK ALL above the list — see Backup & Sync.

Creating a New Script

Tap + NEW in the header. DeepTap creates a script called Script 2, Script 3, etc., puts it at the top of the list and makes it active. The new script starts empty — no steps yet. Tap ▶ to open the toolbar and begin adding steps.

Adding Steps (Taps and Sweeps)

When you press ▶ on a script, a floating toolbar appears on your screen. From here you add and play steps:

  • Add a click — tap ＋ Click. A green numbered handle appears; drag it to the exact spot you want tapped. DeepTap stores that spot as an absolute coordinate. New actions go to the end of the script.
  • Add a sweep — tap ＋ Sweep. An arrow appears with a numbered handle at each end: the tail is where the finger touches down, the head (the arrowhead) is where it lifts. Drag either handle to move that end, or press and drag the arrow's line to move the whole sweep without changing its direction or length.
  • Remove a step — tap its handle and press × Delete in the panel, or select its tile in View Script and tap 🗑.

Handles are green; violet when the action has a WHEN condition; dimmed when the action is disabled. While a script is playing, handles and arrows ignore touches.

Important: Steps are recorded in absolute screen coordinates. If you record a tap at position (500, 1000) on a phone with a 1080×2400 screen, that same tap will attempt to hit (500, 1000) on any device, regardless of screen size. If you run the script on a different phone, taps may miss their targets. Re-record or edit steps if you switch devices.

Organizing and Reordering Steps

Two places let you check and change steps.

View Script (toolbar ⚙ View Script → ◈ ACTIONS) shows every action as a numbered tile. Tap a tile to see its details — hold or speed, waiting time, Advanced: ON / off, the process and detector it uses — and these buttons:

  • 🗑 delete · the eye (show or hide its handle) · ✎ EDIT (open the edit panel) · ↑ UP / ↓ DOWN (move it one place).
  • ◎ RESET POSITION — brings the action to the centre of the screen. Use it when a handle ended up off-screen; a sweep keeps its direction and length.
  • An action that repeats shows ×N after its title, e.g. CLICK #03 ×3.

The edit panel (tap a handle, or ✎ EDIT) has three tabs:

  • PARAMS — WAITING (ms): the pause after this action before the next one. TIME HOLD (ms) for a click, or SWEEP SPEED (ms) for a sweep. REPEAT (times): 1 = once; 3 = action → waiting, three times in a row. INDEX: type a position 1…N and the action moves there when you Save. Enabled: off = skipped during playback but kept in the script.
  • MOVE — ORDER with ▲ Up / ▼ Down. For a sweep, POINT ① Head / ② Tail picks which end you move (Head, the arrowhead end, is selected first). MOVE ±1: the arrows nudge 1 px per press, or type x,y in the box in the middle (e.g. 540,1200) and press Done — the point is kept inside the screen. Changes on MOVE apply at once.
  • RULE — turn on ADVANCED to give the action its own rule: WHEN (condition) (None (always run) or a detector, with Invert), THEN (actions) and OUTCOME (Continue / Reset loop / Stop). THEN actions run top to bottom; reorder them with ▲ / ▼, remove one with ✕, add one with + Add action. See Process for what each action does.

Loop Count — How Many Times to Run

Open ⚙ View Script → ⚙ CONFIG. The LOOP field controls how many times DeepTap repeats your entire script:

  • Enter 0 to run forever (infinite loops).
  • Enter any positive number (1, 5, 100, etc.) to run exactly that many times.

Example: If your script has 3 steps and you set the loop count to 5, DeepTap will run all 3 steps, then start over from step 1, repeating 5 times total.

Script Menu — Rename, Duplicate, Delete, Post-Loop

Tap the menu button ⋮ next to a script row. You'll see four options (and Cancel):

  • Rename — change the script's name to something memorable (e.g., "Tap Loop", "Spin Wheel").
  • Duplicate — create an exact copy of the script with a new name (e.g., "Tap Loop copy"). Useful for testing variations without losing the original.
  • Edit post-loop — attach a process that runs once every loop, at the loop's start or at its end. See the Post-Loop section below.
  • Delete — remove the script permanently. DeepTap prevents you from deleting your last script — you must always have at least one.

Post-Loop: Run a Process Every Loop

DeepTap can run a post-loop process once in every loop of your script — any process with Show in post-loop picker switched on (e.g. the bundled SIMPLE Close Popup Process) that handles things like popups.

To set this up, tap ⋮ > Edit post-loop. The dialog Post-loop process opens:

  • Turn on Run a process every loop.
  • Run at — choose when it runs. Loop start (the default): before the first action of every loop, including loop 1 right after you press Play; it does not run again after the last loop. Loop end: after the last action of every loop. Either way it runs once per loop. Tap ? next to Run at for a short reminder (× hides it).
  • Pick the process from the list — ● marks the selected one. If the list is empty you'll see No eligible process. Create one first.
  • Tap Save to apply changes.

Upgraded from an older version? Scripts that had post-loop on before Run at existed now run it at Loop start. To keep the old timing, open Edit post-loop, choose Loop end and tap Save.

When a process resets the loop: playback goes back to loop 1. If the post-loop process itself returns Reset at Loop start, the actions of loop 1 run first and the process waits for the next loop — so a screen that hasn't changed yet can't keep resetting. If a process inside an action resets the loop, the new loop 1 starts with the post-loop process as usual (Loop start); with Loop end, the interrupted loop gets no post-loop run.

Example: You have a script that repeats a task each loop, and a popup sometimes covers the screen. Enable post-loop and select a process (e.g. the bundled "SIMPLE Close Popup Process") — DeepTap clears that popup once every loop, then continues without interrupting you.

The ⚙ CONFIG tab of View Script also has a POST-LOOP switch and process picker, but no Run at choice — switching it there keeps the Run at you chose here.

Copying Scripts from Another Device

You can copy a script from a backup — your own, one sent from another device, or the built-in sample. Tap ⧉ COPY in the header:

  1. Pick a source — 📦 Sample (built-in), your backups on this device (name (Local) · dd/mm hh:mm), or ＋ Browse a backup file (Local) for a file someone shared with you. In builds with a sync server and PRO MODE on, server backups are listed too. Tap one to see its scripts.
  2. Check the status — each script shows a badge:
    • NEW — script doesn't exist on this device; tap Copy to add it.
    • HAVE — you already have this script with identical steps and settings; copying is not needed.
    • DIFF — you have a script with the same name but different steps or settings (e.g., different loop count). Tap Copy to overwrite yours with the remote version.
  3. Confirm and copy — tap Copy, confirm in the popup, and DeepTap copies the script to your device (a script with the same name is overwritten).

The script brings what it needs. If it uses processes or detectors you don't have — its post-loop process (while switched on), a process attached to an action, a Run process inside THEN, a WHEN detector or a Click button detector — DeepTap lists them in Copy dependencies too?. Copy all copies them along with the script; Cancel copies nothing. Missing items are found by name.

Tip: Copying is useful when you've tested a script on one phone and want to quickly set it up on another, or when a friend shares a working script.

Starting and Stopping Playback

Once you have a script with steps, press ▶ START to begin:

  • DeepTap shows the floating toolbar on top of that app.
  • It runs through all enabled steps in order, then loops back if the loop count is more than 1.
  • If post-loop is on, DeepTap runs the selected process once every loop — before the loop's first action (Loop start) or after its last action (Loop end).
  • While it plays, the toolbar's play button turns into a red square. Tap it anytime to stop immediately.

DeepTap continues running in the background — you can use other apps or put your phone in your pocket. The script keeps playing.

Warning: Do not uninstall DeepTap or revoke permissions (Accessibility Service or Overlay) while a script is running. This may cause the phone to lock or the script to stop unexpectedly. Always tap ⏹ Stop first if you need to change settings.

Detectors: Recognize Popups and Screens

A detector teaches DeepTap how to recognize when a specific popup or screen appears on your phone. It works by looking for visual markers (like a "close" button or a unique icon) in a specific region of the screen. Once it recognizes them, DeepTap can trigger actions or skip to the next step in your script.

How a Detector Works

Every detector has three parts:

  1. Buttons — visual markers you want to find (like a popup close button or a target button). Each button has a code name (e.g., BTN_CLOSE) and a description.
  2. Identifier Rule — which buttons must match before the detector "fires". Choose AND (all marked buttons must be found) or OR (any one marked button found is enough).
  3. Threshold — how similar the on-screen button must look to the template you captured. Default is 90% (0.90). Higher = stricter matching.
Templates are device-specific: when you capture a visual marker (crop it from your screen), DeepTap saves a PNG snapshot for this phone's resolution. If you copy a detector from another device, its templates copy too so DeepTap matches immediately.

Sample Detectors (Editable Seed Data)

DeepTap has no hard-coded detectors. On a fresh install it seeds 4 sample detectors — ordinary data you can edit, copy or delete like any other (the 📦 Sample backup carries them too):

  • SIMPLE Popup1 and SIMPLE Popup2 — recognize a popup (identifiers BTN_POPUP1/BTN_POPUP2, plus the action button BTN_COLLECT to tap).
  • ADVANCE Popup Close Button — recognizes the × button that closes a popup, using the marker BTN_CLOSE.
  • ADVANCE Popup Gone — recognizes that a popup has gone away and you're back on the screen behind it (marker BTN_GONE).

These are used by the bundled SIMPLE/ADVANCE Close Popup processes. You can also copy a sample detector's regions and templates from another device so you don't have to re-crop on this device.

Create or Edit a Detector

Open the DETECTORS tab at the bottom of the app to manage your detectors (newest at the top):

  1. Tap + NEW to create a new detector, or tap an existing detector name to edit it.
  2. Enter a detector name and set the Threshold (%) — usually 90 is fine. Lower values (e.g., 70) are more forgiving if the button looks different each time; higher (95+) are stricter.
  3. Choose your identifier rule: AND or OR.
  4. In the BUTTONS section, tap + Add button to add each visual marker you want to find.
    • Enter a button code (e.g., BTN_CLOSE, BTN_TARGET).
    • Add a description (what is this button?).
    • Tick identifier on the buttons that decide whether the detector fires (combined by the AND / OR rule). An unticked button is only a tap target. At least one button must be ticked.
    • Choose its match methods (tried in order, tick at least 1) — see the table below. Tap ? next to any tick for a short explanation.
  5. Tap SAVE.
Renaming a button code? DeepTap automatically keeps the identifier tick in sync — if you rename a ticked identifier button, it stays ticked.

Crop a Template (Region)

After you save a detector, you must capture a visual template so DeepTap knows what to look for. This happens on the floating toolbar, over the app you are automating:

  1. Open the toolbar menu → List Detector and tap the detector's name. Its panel, Current Detector, lists the detector's buttons and their regions (newest region at the top).
  2. On a button, tap ＋ Add. A small region (15 × 15 px) appears in the middle of the screen: an orange dashed box labelled NN · BUTTON, joined to a knob below it.
  3. Move and size the box to frame the button or marker you want to capture:
    • Drag the knob. With LOCK on (green knob with 🔒, the default) the whole box follows; with LOCK off (orange numbered knob) only the knob moves.
    • Tap the knob, or the region's #NN in Current Detector, to open the region panel: WIDTH / HEIGHT sliders (up to 300 px) and − / + for the size, MOVE ±1 arrows to nudge it 1 px at a time.
  4. Tap Crop to take a screenshot of that region and save it as your template (it shows under TEMPLATE). Then tap Save.

The region panel also has the eye (show or hide this region on screen — hidden regions still match), an OK / Not Ready chip to mark regions you have finished (it doesn't change matching), PRIORITY: NORMAL / HIGH (HIGH regions are checked first), ◈ TEST and ◉ CLICK. Changes apply as you make them — Cancel does not undo them. Only cropped regions are used for matching.

Understanding Processes in DeepTap

A process in DeepTap is a mini decision-maker. It can run once every loop as a script's post-loop process, inside an action's rule, or from another process. Think of it as a series of "if this happens, do that" rules that DeepTap checks in order. The first matching rule wins and the others are skipped.

Why Use Processes?

Processes handle unexpected situations that pop up during play:

  • Closing a popup that appears after an action
  • Handling popup messages or dialogs
  • Deciding when to stop or reset the script
  • Redirecting DeepTap's actions based on what's on screen

How a Process Works: WHEN → THEN → OUTCOME

Every rule in a process has three parts:

Part What it Does Examples
WHEN (Condition) A check DeepTap makes on screen. If it matches, the rule fires. "If a popup close button appears" or "If battery drops below 20%"
THEN (Actions) One or more things DeepTap does in sequence when the condition matches Wait 500ms, then click the close button
OUTCOME (Flow Control) What DeepTap does after the actions finish Keep looping, reset to the start, or stop the script

WHEN: Conditions

DeepTap checks the condition against what's currently on screen:

  • Always — This condition always matches. Useful as a fallback rule at the bottom of your process to handle cases nothing else caught.
  • Detector match — DeepTap looks for a named detector (a region you taught it to recognize, like "popup_close_button"). You can pick any detector you've created in the Detector section.
  • Invert — Toggle this on to reverse the condition. For example, "if popup_close_button does NOT appear" instead of "if it does".
  • Battery level — DeepTap checks the device battery and triggers if it's below or above a percentage you choose (default 20%).
How conditions work: A condition either matches or it doesn't. If it matches, DeepTap runs the THEN actions and then follows the OUTCOME. If it doesn't match, DeepTap skips this rule entirely and checks the next one.

THEN: Actions

When a condition matches, DeepTap runs its actions in order, one after another:

  • Wait — Pause for a number of milliseconds (1000 ms = 1 second). Useful to let animations finish before clicking.
  • Click button — Click a specific button belonging to the detector in your WHEN condition. When you pick "Click button", DeepTap shows you a list of buttons available on that detector; pick the one to tap.
  • Send Back — Press the device back button one or more times. Useful to dismiss dialogs.
  • Send Home — Press the home button, returning to the home screen.
  • Send Recents — Press the Recents (app overview) button.
  • Scroll — Scroll the screen in the direction you choose.
  • Send Text — Type a text into the field that has focus.
  • Send Enter — Press Enter in the field that has focus (Android 11+).
  • Capture — Save a screenshot on the device (browse them in CONFIG → General → SCREENSHOTS → VIEW).
  • Notify Discord — Send a message to your own Discord webhook (CONFIG → Advance → DISCORD NOTIFY).
  • Perform action (caller) — Do the tap or swipe of the action whose rule started this process. In an action's own RULE tab it is called Do this action.
  • Lock Screen — Lock the device immediately (Android 9+).
  • Run Process — Call another process inline, like a nested mini-script. When that process finishes, control returns to the current one. If the nested process ends with Stop or Reset, those results short-circuit the parent process too.
Action order matters: DeepTap runs actions in the order you list them. If you wait 2 seconds then click, DeepTap will actually wait first, then click. Reverse the order and the timing changes.

OUTCOME: What Happens Next

After all actions finish, the outcome tells the playback engine what to do:

  • Continue — Start the next playback loop immediately. Use this when you've handled the situation and DeepTap should keep doing its normal task.
  • Next Step — Skip ahead to the next step in this process. DeepTap re-scans the screen and checks the next step's condition.
  • Go to Step N — Jump to a specific earlier or later step. DeepTap re-scans and checks that step's condition. Useful for loops: a step can jump back to itself until a condition changes.
  • Reset — Restart the main playback loop from the beginning. Useful when the screen changed significantly.
  • Stop — End the script run. The playback engine stops and returns to idle.
  • Chain → [Process name] — Run another process after this one finishes. When you pick this outcome, choose which process to run. Common use: after a process finishes, chain to the "ADVANCE Close Popup Process".

Creating and Editing a Process

In the Processes screen:

  1. Tap + New to create a new process, or tap an existing process name to edit it.
  2. Enter a name for the process (e.g., "Handle Popups").
  3. Switch on Show in post-loop picker if you want to attach this process to a script as its post-loop process (it then runs once every loop). Leave it off if this process should only run when called by another process via the Chain outcome or Run Process action.
  4. Set Max Duration (minutes) — the longest this process is allowed to run. If it takes longer, DeepTap stops it and returns Continue. Default is 10 minutes. This prevents infinite loops.
  5. Tap + Add Step to add a new rule (step).
  6. Tap a step to expand it and edit the WHEN, THEN, and OUTCOME.
  7. Reorder steps by tapping the up/down arrows.
  8. Tap Save when done.

Non-Matching Steps

If a step's condition does not match, DeepTap skips that step's actions without firing them and moves to the next step. This makes it efficient: only the first matching step runs; everything else is bypassed.

The Bundled Sample Processes: SIMPLE & ADVANCE Close Popup

DeepTap seeds two editable sample processes that demonstrate the detector→process system end to end. They are ordinary data — you can edit, copy or delete them, and the 📦 Sample backup carries them too. Both have Show in post-loop picker on, so either can be attached as a script's post-loop process.

SIMPLE Close Popup Process — one step per popup: WHEN the SIMPLE Popup1 (or SIMPLE Popup2) detector matches → tap its BTN_COLLECT button → Run Process → ADVANCE Close Popup Process to dismiss whatever popup follows.

ADVANCE Close Popup Process — a six-step loop that hunts the popup's close (×) button:

  • Steps 1–2: the ADVANCE Popup Gone detector must match twice before the process finishes: the first sighting arms it, then it waits 3 seconds and re-checks; the second sighting waits 2 more seconds and returns Continue.
  • Step 3: while "gone" is not confirmed, it sends Back twice, 200 ms apart, then re-scans.
  • Steps 4–5: the ADVANCE Popup Close Button detector (the ×) — on every 3rd sighting it presses Back first and re-scans; if the × is still there it taps BTN_CLOSE, waits 3 seconds and starts over.
  • Step 6: nothing found — it waits 3 seconds and starts over.
  • Max duration 180 s — if the popup still isn't gone by then, it runs ADVANCE Popup Timeout: take a screenshot, send a Discord notification, and stop the script.

A fresh install gets this version. An older install keeps its own copy until you copy the process again from 📦 Sample (built-in).

Use them as templates for your own detect-then-act flows: chain to the ADVANCE closer from any process that needs to dismiss a popup after acting, or copy either one and adapt it.

Copying a Process from Another Device

You can copy a process from a backup — your own, a file sent from another device, or the built-in 📦 Sample (in builds with a sync server and PRO MODE on, server backups too):

  1. In the Processes list, tap ⧉ COPY.
  2. Pick the source whose processes you want to copy.
  3. DeepTap scans the selected process for dependencies — detectors or child-processes it references.
  4. A badge shows the status of each process:
    • NEW (green) — This process doesn't exist on your device yet. DeepTap will copy it.
    • DIFF (orange) — A process with the same name exists locally, but it's different. DeepTap offers to overwrite it.
    • HAVE (gray) — This process already exists locally and is identical. Nothing to copy.
  5. Tap Copy. If the process depends on detectors or child-processes you don't have, DeepTap offers to copy those too in a cascade. This is often faster than recreating them manually.

Process Nesting with Run Process

Processes can call other processes using the Run Process action. There is a depth cap to prevent infinite recursion, and each process has its own per-invocation Max Duration limit. When a nested process returns Stop or Reset, that result is passed up to the parent immediately.

Using a Process as a Post-Loop Hook

If a process has Show in post-loop picker on, you can attach it to a script: HOME → the script's ⋮ → Edit post-loop (see Post-Loop in the Script section). It then runs once every loop — at the loop's start (the default) or at its end. The process's OUTCOME determines whether the loop continues, resets, or stops.

Organizing processes: Keep your processes simple. A 3–5 step process is easier to debug than a 20-step one. If you find yourself nesting many levels, consider splitting complex logic into multiple smaller processes that chain to each other.

Default Max Duration

The default max duration for a new process is 10 minutes (600,000 milliseconds). You can lower this if you're worried about loops, or raise it if your process legitimately needs to run longer. Set it to 0 to disable the timeout (unlimited).

AI Assistant — Build Processes with ChatGPT

On the PROCESSES screen a floating AI button opens the AI Assistant — a helper that lets an AI chatbot (e.g. ChatGPT) design or modify your processes and detectors for you. You describe what you want in plain words, in any language, and paste the AI's answer back into DeepTap:

  1. COPY FOR AI — puts an instruction prompt plus your current processes and detector schemas on the clipboard.
  2. Paste into ChatGPT — paste the clipboard into any AI chat and describe the automation you want.
  3. Paste the answer back + CHECK — DeepTap validates ids, references and structure, then shows a summary of what would change.
  4. APPLY — DeepTap saves a safety backup first, then merges the changes by id.

🐞 DEBUG BUNDLE FOR AI (under COPY FOR AI) is for when something goes wrong: it packs everything at once — scripts, processes, detectors, the region images and the run log — so an AI can replay what happened step by step. Up to about 512 KB goes to the clipboard; a bigger bundle opens the share sheet as a file. The run log comes from DETAIL LOG (on by default); if it is off, turn it on, reproduce the problem once, then export again.

Because merging is by id, existing items are updated in place and new ones are added — nothing else is touched. Newly created detectors have no regions yet: open each one in Current Detector, tap ＋ Add, place the box over the real button and Crop a template before running. If anything looks wrong after APPLY, restore the safety backup.

Timing and Performance: Make DeepTap Fast (or Patient)

DeepTap has five timing settings in CONFIG → Advance → TIMING. The section is folded away — tap SHOW to open it (it folds again each time you open Config). They control how long a tap is held, how quickly DeepTap scans the screen, how long it waits before tapping, and how much memory each scan uses. Each field has a ? with a short explanation.

The Five Settings

Setting What it does Default Range
CLICK HOLD How long the finger stays down in one tap made by a process or an action rule (Click button), and by the region panel's ◉ CLICK. A script's own clicks use their TIME HOLD instead. 50 ms 10–2000 ms
SCAN INTERVAL Minimum time between screenshots (floor: 333ms, set by Android) 500 ms 333–5000 ms
CLICK DELAY Wait time after detecting a button before tapping it 500 ms 0–5000 ms
RE-SCAN AFTER How stale a screenshot can be before DeepTap re-captures (0 = off) 500 ms 0 or 500–60000 ms
MATCH RESOLUTION Shrink screenshots before matching to save RAM (0 = full-res, no shrink) 0 (off — full resolution) 0 or 480–4000 px

Why These Matter

SCAN INTERVAL is a hard floor enforced by Android's accessibility layer. If you fire two screenshots back-to-back faster than 333ms apart — which happens when a child process runs inside a parent process, or when DeepTap double-checks a screen — the second one fails silently and returns nothing. This was mistakenly blamed on the old Slow-Log toggle (since replaced by DETAIL LOG) before the problem was understood: its ~1-second pause accidentally spaced out the two screenshots enough to work. Now SCAN INTERVAL fixes it automatically. Don't set it below 333ms; Android will ignore it anyway.

CLICK DELAY pauses between the moment DeepTap detects a button and the moment it taps. This is necessary because:

  • A button that just appeared may still be animating in and not yet interactive.
  • A tap fired immediately after a screenshot can be cancelled by the system.

Set to 0 to disable. On fast devices, you can lower this to 100–200ms. On slow devices, raise it to 1000ms or more.

CLICK HOLD matters mostly on emulators: if a tap is too short, some of them show the button's highlight but never register the click. Raise it (e.g. 100–200 ms) if taps from a process light up the button but nothing happens.

RE-SCAN AFTER handles a subtle problem: if a process takes a long time inside a single step (like a long Wait or a child process that keeps polling), the screenshot DeepTap took at the top gets stale. When it finally tries to click, the screen may have changed. DeepTap will re-screenshot and check again; if the button moved or disappeared, it skips the click safely instead of tapping a ghost. Set to 0 to turn off and always use the original screenshot. Minimum 500ms (below that, Android throttles it anyway).

MATCH RESOLUTION shrinks the captured screenshot before comparing it to saved patterns. A full-screen photo on modern phones is ~13 MB and held in memory for the entire scan. On low-RAM devices, this causes lag and garbage-collection freezes. By capping the longest side to, say, 1600 pixels, DeepTap throws away the full-res copy right away and keeps only the smaller version. Since DeepTap already downscales every region to 64×64 for comparison, a moderate shrink barely hurts accuracy. The default is 0 — full resolution, no shrink; set a pixel cap (e.g. 1600) only if a low-RAM device lags or freezes. Only screens larger than the cap are downscaled; smaller screens are unchanged.

When to adjust these:
  • DeepTap misses buttons or never runs nested processes: Raise SCAN INTERVAL to 400–600ms or higher (some Android versions enforce a longer interval than 333ms). Also check that MATCH RESOLUTION is 0 (full resolution) so small buttons keep their detail.
  • Taps don't register or tap the wrong spot: Raise CLICK DELAY to 800–1500ms so the button settles before DeepTap taps.
  • The button lights up but the tap does nothing (often on emulators): Raise CLICK HOLD to 100–200ms.
  • Device gets hot or slow during a long script: Set a MATCH RESOLUTION cap to save RAM — try 1600 first, then 1200; don't go below 480 or tiny icons will blur too much.
  • DeepTap catches the screen mid-animation and clicks the wrong element: Raise RE-SCAN AFTER to 5000–10000ms so stale screenshots trigger a fresh capture sooner.

System Stats Strip

Toggle SHOW SYSTEM STATS (CONFIG → Advance → LOG) to see a RAM and battery indicator while DeepTap runs. This shows you in real-time if a setting change (especially MATCH RESOLUTION) is cutting memory use. Watch for dips in free RAM or spikes in battery drain as clues to cap MATCH RESOLUTION (or lower an existing cap further).

Important: The timing settings are applied when you press SAVE at the bottom of Config (Config then closes). Changes take effect immediately; you don't need to restart DeepTap or the app.

Screenshots & Logs

SCREENSHOTS is on the General tab of CONFIG: captures stay local-only on the device — tap VIEW to browse the saved shots. The Advance tab has the LOG section — LIVE LOG (off by default: process and detector messages on the toolbar strip), DETAIL LOG (on by default: a readable step-by-step engine trace that keeps the latest 10,000 characters; open it from the toolbar menu → Log detail, with COPY and CLEAR) and SHOW SYSTEM STATS — plus DISCORD NOTIFY.

Save and Test

After adjusting any timing setting:

  1. Tap Save at the bottom of Config.
  2. Close Config and start a test script or capture.
  3. Watch the log or enable SHOW SYSTEM STATS to see if the change helped.
  4. If it didn't, adjust again and test—there's no penalty for tweaking.

Backup & Sync Across Devices

DeepTap can back up your automations and move them between your phones, tablets and emulators. This section explains backups, the important difference between copying one item and restoring everything, and — in builds with a sync server — how to keep the same detectors, processes and scripts on all your devices.

Which parts you have depends on your version. Backups on the device (and as a file in Downloads), Share, ⧉ COPY and ↺ RESTORE from a backup on the device work everywhere. Everything that uses a server — backing up to the server, copying or restoring a server backup, Merge, ⟳ SYNC ALL, ↑ UPLOAD / ↓ DOWNLOAD, CHECK and the web dashboard — needs a sync server and PRO MODE on (CONFIG → General). The Google Play version has no server, so those buttons never appear there.

How Backup Works

Open CONFIG → General → BACKUP and tap ⤴ BACKUP. The button shows a spinner and a percentage while it works. The backup includes:

  • All scripts (the sequence of tap/swipe actions you've recorded)
  • All detectors (the patterns DeepTap learns to recognize on screen)
  • All processes (your automation rules and logic)
  • Button regions (the exact screen positions where DeepTap clicks)
  • Template images (the cropped screenshots DeepTap uses to find buttons)

Where it goes is set by BACKUP DESTINATION:

  • LOCAL — saved in the app and as a file in Downloads, DeepTap_USERNAME_date.txt (an older file with the same name is replaced). This is the only choice in the Google Play version, and the only one while PRO MODE is off.
  • SERVER (sync-server builds, PRO MODE on) — uploaded to your account. All devices that use the same USERNAME share this one server backup: each server backup replaces it.

Share saves a fresh backup with its templates and opens Android's share sheet — send it by Gmail, Zalo, Messenger or Drive to another device, then bring items in there with ⧉ COPY → ＋ Browse a backup file (Local).

Setting Your Username and Backup Password

Both fields are in CONFIG → General → BACKUP. The server needs both — server backup, restore and sync are refused without them. Local backups need neither.

  • USERNAME — your account, and the sync hub that Merge, Upload and Download go through. 3–64 characters: letters, digits and . _ + -. The first server action registers it, so a typo silently creates a new, empty account.
  • BACKUP PASSWORD — at least 6 characters, checked by the server so another device using the same username cannot overwrite your data. It is not a login.

Use the same USERNAME and password on every device you own — that is what lets a phone restore what a tablet backed up, and what makes Merge, Upload and Download work between them. On a fresh install USERNAME is pre-filled with your phone model and a number (e.g. 2412DPC0AG-6401) and the password is empty: change the username to something you'll recognise before your first server backup. ⤴ BACKUP and ↺ RESTORE use what you have typed, even before you press SAVE.

A device can't see your backup or synced items? Check that its USERNAME and password are the same as on your other devices — a different USERNAME is a different account.

Copy from a Backup (Non-Destructive)

Use ⧉ COPY to safely grab a single automation without affecting your own work. It is in the header of each list: HOME (scripts), PROCESSES and DETECTORS.

Where you can copy from: 📦 Sample (built-in); your backups on this device (name (Local) · dd/mm hh:mm); ＋ Browse a backup file (Local) for a file someone shared with you; and, in sync-server builds with PRO MODE on, your account's server backup and backups shared with you.

What gets copied:

  • For a detector: the detection pattern, all its button regions, and their template images
  • For a process: all the automation rules — plus the detectors and child processes it needs, if you confirm
  • For a script: the recorded tap/swipe sequence — plus the processes and detectors it uses, if you confirm

How it handles conflicts:

  • An item with the same name on this device is replaced — just that one
  • All your other automations stay exactly as they were
  • Regions keep their pixel positions; on a screen with another resolution you may need to move and re-crop them (see below)

Step by step (scripts, processes and detectors work the same way):

  1. Tap ⧉ COPY in the list's header
  2. Pick a source
  3. Tap the item you want — its badge says NEW, HAVE or DIFF
  4. If it uses detectors or processes you don't have, DeepTap lists them in Copy dependencies too? — tap Copy all to copy them along, or Cancel to copy nothing
  5. Confirm the copy — done
Cascade copying: processes and scripts bring the items they depend on, found by name, so nothing ends up pointing at something this device doesn't have. A detector has no dependencies to bring.

Restore Full Backup (Destructive — Back Up First!)

Use ↺ RESTORE (CONFIG → General → BACKUP) only when you want to completely replace this device's automations with a full backup. This is typically used when:

  • You've uninstalled and reinstalled DeepTap and want your old automations back
  • You're cloning your entire setup from one device to another (and you don't care about work on the target device)

What Restore does:

  • Replaces all detectors, processes, and scripts with the backup's versions
  • Replaces every button region with the backup's — regions you added locally are deleted, together with their cropped images
  • Erases anything on your device that isn't in the backup

Before you Restore:

  1. Set BACKUP DESTINATION to LOCAL and tap ⤴ BACKUP to save this device's automations
  2. Check that it says Backed up to Local ✓
  3. Now you can safely tap ↺ RESTORE and pick the backup in Restore from… — if something goes wrong, restore your local backup

Templates & Screen Resolution

Button templates (the cropped screenshots DeepTap uses to find and click buttons) are tied to your device's screen resolution. When you copy or merge a detector from another device:

  • Same resolution: Templates copy perfectly and work immediately
  • Different resolution: regions keep their pixel positions and templates their size, so they may miss — move the regions and re-crop on this device

This is why devices with identical screen sizes (like the same emulator or phone model) work best for sharing.

Web Dashboard Access

In sync-server builds, your backups can also be viewed and managed from a web dashboard, kept by whoever runs the server. It is protected with a login, and the address is not something you enter in the app any more. From there they can:

  • See all your device backups and their timestamps
  • Preview detectors, processes, and scripts
  • Edit automations before loading them to another device

Common Patterns

Pattern 1: One account, many devices

Use the same USERNAME and password on every device. Improve an automation on any of them, then Merge the detector or ↑ UPLOAD the process or script. On your other devices press CHECK ALL to see what changed, then ⟳ SYNC ALL (detectors) and ↓ DOWNLOAD / ↓ DOWNLOAD ALL (processes, scripts).

Pattern 2: New or reset device

  1. Enter the same USERNAME and BACKUP PASSWORD as on your other devices
  2. Either tap ↺ RESTORE and pick your account's backup (this replaces everything on the device)…
  3. …or keep what is there and pull the synced items: ⟳ SYNC ALL on DETECTORS, then ↓ DOWNLOAD ALL on PROCESSES and on HOME

Pattern 3: Testing New Automations

You want to try a new process without risking your main setup. Use a second device (or emulator):

  1. Copy just the detector(s) you need with ⧉ COPY — for example from a backup file you shared from your main device
  2. Build and test the new process safely
  3. Once it works, bring it to your main device — with Share and ⧉ COPY, or with ↑ UPLOAD here and ↓ DOWNLOAD there
Remember: ⧉ COPY is your friend for sharing small pieces. Restore is for full replacements. Merge, Upload and Download keep the same items in step across your devices. When in doubt, back up first.

DeepTap hoạt động thế nào: cách nghĩ tổng quát

DeepTap là một ứng dụng tự động bấm cho Android, giúp bạn ghi lại rồi phát lại các thao tác chạm và vuốt trên màn hình điện thoại, sau đó chạy tự động theo vòng lặp. Nhưng DeepTap còn thông minh hơn thế: nó có thể quan sát những gì đang hiện trên màn hình và tự quyết định bước tiếp theo — chẳng hạn đóng một popup hoặc bấm một nút ngay khi nút đó xuất hiện.

Để hiểu DeepTap, bạn chỉ cần nắm bốn ý chính:

1. Script: chuỗi thao tác bạn đã ghi

Một Script là chuỗi các thao tác chạm và vuốt mà bạn ghi lại. Mỗi Action được lưu kèm vị trí chính xác trên màn hình (toạ độ). Khi bạn nhấn Play, DeepTap lặp lại các thao tác này nhiều lần, đúng bằng số vòng lặp bạn đặt. Bạn cứ hình dung nó như một macro: chạm chỗ này, vuốt chỗ kia, rồi chạm tiếp.

  • Click: một cú chạm tại một vị trí cụ thể trên màn hình
  • Sweep: một cú kéo từ vị trí này sang vị trí khác
  • Số vòng lặp: chạy toàn bộ Action bao nhiêu lần (≥1). Đặt bằng 0 để tạm tắt Script mà không cần xoá.

Mỗi Script có một tên và có thể chứa nhiều Action. Bạn có thể tạo nhiều Script và chuyển qua lại giữa chúng.

2. Detector: nhận ra thứ đang hiện trên màn hình

Một Detector là cách DeepTap nhận ra những thứ xuất hiện trên màn hình — ví dụ một popup hay một nút đóng. Thay vì bấm mù cùng một chỗ hết lần này đến lần khác, DeepTap có thể nhìn xem ở đó có gì rồi phản ứng theo.

Detector hoạt động ra sao? Nó đối chiếu một ảnh mẫu nhỏ (gọi là Template) với những gì đang hiện trên màn hình, chỉ tìm trong một vùng nhất định (gọi là Region). Nếu hai bên giống nhau đủ nhiều, DeepTap biết thứ đó đang có mặt. Ví dụ:

Ví dụ: Bạn muốn DeepTap đóng một popup. Bạn cắt ảnh nút đóng của popup (dấu ×), lưu ảnh đó làm Template, rồi chỉ cho DeepTap biết cần tìm nó ở chỗ nào trên màn hình. Mỗi lần quét màn hình, DeepTap kiểm tra vùng đó và so với Template. Nếu thấy nút ×, nó biết đang có popup mở.

DeepTap tạo sẵn 4 Detector mẫu để bạn học theo và chỉnh sửa thoải mái (SIMPLE Popup1, SIMPLE Popup2, ADVANCE Popup Close Button, ADVANCE Popup Gone), và bạn có thể tự tạo thêm bao nhiêu tuỳ thích.

3. Process: bộ não ra quyết định

Một Process là một cỗ máy trạng thái thu nhỏ, dùng Detector để quyết định phải làm gì. Nó là một chuỗi luật NẾU–THÌ. Ví dụ:

  • NẾU phát hiện một popup THÌ bấm nút cần bấm RỒI đóng popup nào hiện ra RỒI Continue vòng lặp
  • NẾU không thấy popup nào THÌ đặt lại bộ đếm vòng lặp và bắt đầu lại từ đầu

Mỗi vòng lặp của Script một lần — mặc định là ngay trước Action đầu tiên của vòng — DeepTap có thể chạy một Process để soi màn hình và ra quyết định:

  • Continue: tiếp tục lặp
  • Reset: đếm lại vòng lặp từ 1
  • Stop: dừng chạy

Process giống như một công thức nấu ăn: bạn ghi ra các bước, và DeepTap làm theo đúng như vậy mỗi lần.

4. Region + Template: tìm ở đâu và tìm cái gì

Một Region là một vùng hình chữ nhật trên màn hình. Một Template là ảnh chụp nhỏ (file PNG) của thứ bạn cần tìm. Ghép lại, chúng nói với DeepTap rằng: "Hãy nhìn vào trong khung này và so những gì thấy được với tấm ảnh này."

Mỗi lần quét, DeepTap chấm điểm xem Template giống với nội dung trong vùng đó đến đâu — điểm từ 0% đến 100%. Nếu điểm đạt ngưỡng của Detector (thường là 90%), coi như khớp.

Quan trọng: Region và Template gắn với từng máy. Nếu bạn chuyển ứng dụng sang điện thoại khác, toạ độ có thể không còn đúng. Bạn vẫn sao chép được Script và Process giữa các máy, nhưng phải chụp lại Template trên máy mới.

Hai chế độ: chế độ chỉnh sửa và chế độ chạy

Chế độ 1: chỉnh sửa — dựng Script của bạn

Khi mở DeepTap, bạn đang ở chế độ chỉnh sửa. Đây là nơi bạn:

  • Tạo và đặt tên cho Script
  • Ghi lại các cú chạm và vuốt bằng một nút trên thanh công cụ nổi
  • Xem trước các Action ngay trên màn hình (có các nút kéo và núm chỉnh)
  • Đặt số vòng lặp và giới hạn thời gian
  • Gắn một Process chạy mỗi vòng một lần, ở đầu vòng hoặc ở cuối vòng (kiểu như "bấm một nút khi nó xuất hiện rồi đóng popup")

Ứng dụng vẫn nằm ở tiền cảnh, và bạn thấy một thanh công cụ nổi với các nút để thêm Action, xem Script và bắt đầu chạy.

Chế độ 2: chạy — tự động bấm ở nền

Khi bạn nhấn ▶ START trên một Script, DeepTap chuyển sang chế độ chạy:

  1. Ứng dụng DeepTap lùi xuống nền (bạn nhìn thấy ứng dụng đang được tự động hoá)
  2. Thanh công cụ nổi vẫn ở trên cùng, giờ hiện nút Play/Stop và nhật ký trực tiếp về những gì DeepTap đang làm
  3. DeepTap chạy các Action của Script theo vòng lặp, và quét màn hình giữa các vòng để kiểm tra Detector
  4. Nếu một Detector khớp, Process đã gắn sẽ chạy (ví dụ đóng popup, bấm một nút khi nó xuất hiện)
  5. Nhấn ⏹ STOP để dừng chạy và quay lại chế độ chỉnh sửa
Bạn luôn thấy được DeepTap đang làm gì: dải chữ trên thanh công cụ có hai dòng. Dòng 1 là tiến độ, ví dụ L6/10 A4 · 12s (vòng 6 trên 10, Action 4, đã chạy 12 giây). Dòng 2 là thông báo mới nhất: các bước của Process, những lần Detector khớp, lỗi và lý do dừng chạy. Thông báo của Process và Detector chỉ hiện ở đó khi LIVE LOG đang bật (CONFIG → Advance). Muốn xem đầy đủ từng bước, hãy mở Log detail trong menu của thanh công cụ — DETAIL LOG bật sẵn theo mặc định. Có gì trục trặc thì những nhật ký này là chỗ đầu tiên bạn nên nhìn.

Thanh công cụ nổi: trung tâm điều khiển của bạn

Khi bạn đang ở chế độ Edit hoặc Play, một thanh công cụ nhỏ nổi lên trên các ứng dụng khác. Nó gồm:

  • Add Click / Add Sweep: Ghi thêm một Action mới (chỉ có ở chế độ chỉnh sửa)
  • ⚙ View Script: Mở lớp phủ hiện toàn bộ Action dưới dạng các ô kéo thả được, kèm các thiết lập riêng của Script (số vòng lặp, giới hạn thời gian, dừng theo pin, khoá máy khi xong)
  • Menu: List Detector / Current Detector (hiện và sửa các Region của một Detector), List PROC (chọn Process cần thử), Test PROC (name) (chạy Process đó một lần, chạy thật — có bấm — để dò lỗi) và Log detail (nhật ký từng bước, khi DETAIL LOG đang bật)
  • ▶ / ⏹ Play / Stop: Bắt đầu hoặc dừng vòng lặp chạy
  • Dải nhật ký trực tiếp: hai dòng trong lúc chạy — tiến độ (ví dụ L1/5 A3 · 2s) và thông báo mới nhất (một bước của Process, một lần Detector khớp, một lỗi, hoặc lý do dừng)

Trình tự cài đặt điển hình

Đây là cách bạn thiết lập DeepTap trong lần đầu tiên:

  1. Tạo một Script: Chạm HOME → + NEW
  2. Ghi các Action: Chạm Add Click hoặc Add Sweep trên thanh công cụ nổi. Chạm/kéo trên màn hình của ứng dụng đích để đặt Action vào đúng chỗ. Làm tiếp cho đến khi ghi xong trọn một "vòng" (ví dụ bấm một nút 5 lần).
  3. Đặt số vòng lặp: Chạm ⚙ View Script → kéo xuống mục LOOP COUNT → nhập số lần lặp lại (ví dụ 10).
  4. Tạo một Detector (không bắt buộc): Chạm DETECTORS → + NEW. Cắt ảnh của thứ bạn muốn nhận diện (chẳng hạn nút trên popup). Lưu ảnh đó làm Template.
  5. Tạo hoặc chọn một Process: Chạm PROCESSES → chọn một Process có sẵn hoặc viết luật mới (ví dụ "Nếu popup xuất hiện thì bấm nút cần bấm, rồi đóng popup").
  6. Gắn Process vào: Vào HOME → chạm menu ⋮ của Script → Edit post-loop → bật lên, chọn Run at (Loop start hoặc Loop end) rồi chọn Process của bạn.
  7. Chạy thử: Nhấn ▶ START và theo dõi nhật ký trực tiếp. Để nó chạy vài vòng. Rồi nhấn ⏹ STOP.
  8. Tinh chỉnh: Nếu Action bấm sai chỗ, chạm ⚙ View Script để sửa toạ độ từng Action. Nếu một Detector không khớp, vào DETECTORS và chỉnh lại Region hoặc Template.
Mẹo hay: Nếu việc nhận diện hoặc bấm chưa ổn định, thử chỉnh SCAN INTERVAL (ms) và CLICK DELAY (ms) trong CONFIG → Advance → TIMING (chạm SHOW). Khi cần dò lỗi, mở Log detail trong menu của thanh công cụ để xem nhật ký từng bước của bộ máy, dễ đọc hơn nhiều (DETAIL LOG bật sẵn theo mặc định).

Script: tạo và quản lý chuỗi thao tác tự động

Một Script là danh sách các cú chạm và vuốt mà DeepTap ghi lại rồi phát lại trên điện thoại của bạn. DeepTap gom hết Script vào một thư viện chung để bạn dễ chuyển qua lại, sửa đổi và chạy bất cứ lúc nào cần.

Danh sách Script (màn hình chính)

Khi mở DeepTap, bạn thấy danh sách Script. Mỗi dòng là một Script kèm đủ thông tin bạn cần:

  • Tên Script — chạm vào tên để đặt nó làm Script đang dùng (hoặc chọn qua menu).
  • Thông tin tóm tắt — N actions · loop N, theo sau là ⟳ process name màu hổ phách khi đang bật một Process post-loop.
  • Nút Play — chạm ▶ để đặt Script làm Script đang dùng và mở thanh công cụ nổi. DeepTap tự lùi xuống nền để bạn nhìn thấy ứng dụng đang được tự động hoá; nhấn Play trên thanh công cụ để bắt đầu chạy.
  • Nút menu — chạm ⋮ (ba chấm) để đổi tên, nhân bản, xoá, hoặc sửa thiết lập post-loop của Script này.

Mẹo: Dòng được viền màu xanh lơ và có nhãn ● ACTIVE chính là Script đang dùng — cái mà thanh công cụ sẽ chạy. Bạn có thể có nhiều Script, nhưng mỗi lúc chỉ một cái được chọn.

Script mới nhất nằm trên cùng danh sách. Ở các bản có máy chủ đồng bộ và đang bật PRO MODE, mỗi thẻ còn hiện version của Script ngay sau tên, cùng các nút ↑ UPLOAD, ↓ DOWNLOAD và CHECK; phía trên danh sách có ↑ UPLOAD ALL · ↓ DOWNLOAD ALL · CHECK ALL — xem Sao lưu & đồng bộ.

Tạo một Script mới

Chạm + NEW trên thanh tiêu đề. DeepTap tạo một Script tên Script 2, Script 3…, đặt nó lên đầu danh sách và đặt làm Script đang dùng. Script mới hoàn toàn trống — chưa có Step nào. Chạm ▶ để mở thanh công cụ và bắt đầu thêm Step.

Thêm Step (chạm và vuốt)

Khi bạn nhấn ▶ trên một Script, một thanh công cụ nổi hiện lên màn hình. Từ đây bạn thêm và chạy các Step:

  • Thêm một cú click — chạm ＋ Click. Một nút tròn màu xanh có đánh số hiện ra; kéo nó đến đúng vị trí bạn muốn bấm. DeepTap lưu điểm đó dưới dạng toạ độ tuyệt đối. Action mới luôn được thêm vào cuối Script.
  • Thêm một cú sweep — chạm ＋ Sweep. Một mũi tên hiện ra, mỗi đầu có một nút tròn đánh số: đuôi mũi tên là chỗ ngón tay chạm xuống, đầu mũi tên (chỗ có mũi nhọn) là chỗ ngón tay nhấc lên. Kéo một trong hai nút để dời đầu đó, hoặc nhấn giữ rồi kéo thân mũi tên để dời cả cú sweep mà không đổi hướng hay độ dài.
  • Xoá một Step — chạm vào nút tròn của nó rồi nhấn × Delete trong bảng chỉnh sửa, hoặc chọn ô của nó trong View Script rồi chạm 🗑.

Nút tròn có màu xanh lá; chuyển sang màu tím khi Action có điều kiện WHEN; mờ đi khi Action bị tắt. Trong lúc Script đang chạy, các nút tròn và mũi tên không phản ứng khi bị chạm.

Quan trọng: Step được ghi theo toạ độ tuyệt đối trên màn hình. Nếu bạn ghi một cú chạm tại vị trí (500, 1000) trên máy có màn hình 1080×2400, thì trên máy nào nó cũng sẽ bấm vào đúng (500, 1000), bất kể màn hình to nhỏ ra sao. Vì vậy chạy Script trên điện thoại khác thì các cú chạm có thể trượt mục tiêu. Khi đổi máy, bạn hãy ghi lại hoặc sửa lại các Step.

Sắp xếp và đổi thứ tự Step

Có hai chỗ để bạn xem và sửa các Step.

View Script (trên thanh công cụ: ⚙ View Script → ◈ ACTIONS) hiện mỗi Action thành một ô có đánh số. Chạm vào một ô để xem chi tiết — thời gian giữ hoặc tốc độ vuốt, thời gian chờ, Advanced: ON / off, Process và Detector mà nó dùng — cùng các nút sau:

  • 🗑 xoá · con mắt (hiện hoặc ẩn nút tròn của nó) · ✎ EDIT (mở bảng chỉnh sửa) · ↑ UP / ↓ DOWN (dời lên hoặc xuống một bậc).
  • ◎ RESET POSITION — đưa Action về giữa màn hình. Dùng khi một nút tròn lỡ nằm ra ngoài màn hình; cú sweep vẫn giữ nguyên hướng và độ dài.
  • Action có lặp lại sẽ hiện ×N sau tiêu đề, ví dụ CLICK #03 ×3.

Bảng chỉnh sửa (chạm vào một nút tròn, hoặc ✎ EDIT) có ba tab:

  • PARAMS — WAITING (ms): khoảng nghỉ sau Action này trước khi sang Action kế tiếp. TIME HOLD (ms) với cú click, hoặc SWEEP SPEED (ms) với cú sweep. REPEAT (times): 1 = chạy một lần; 3 = action → chờ, lặp lại 3 lần liên tiếp. INDEX: gõ một vị trí từ 1…N, khi bạn bấm Save thì Action sẽ dời đến đó. Enabled: tắt = bị bỏ qua khi chạy nhưng vẫn nằm trong Script.
  • MOVE — ORDER với ▲ Up / ▼ Down. Với cú sweep, POINT ① Head / ② Tail chọn đầu nào sẽ được dời (Head — phía có mũi nhọn — được chọn sẵn). MOVE ±1: mỗi lần bấm mũi tên dịch 1 px, hoặc gõ x,y vào ô ở giữa (ví dụ 540,1200) rồi bấm Done — điểm luôn được giữ trong màn hình. Thay đổi ở tab MOVE có hiệu lực ngay.
  • RULE — bật ADVANCED để Action có luật riêng: WHEN (condition) (None (always run) hoặc một Detector, kèm Invert), THEN (actions) và OUTCOME (Continue / Reset loop / Stop). Các hành động THEN chạy từ trên xuống; đổi thứ tự bằng ▲ / ▼, xoá bằng ✕, thêm bằng + Add action. Xem phần Process để biết từng hành động làm gì.

Số vòng lặp — chạy bao nhiêu lần

Mở ⚙ View Script → ⚙ CONFIG. Ô LOOP quyết định DeepTap lặp lại toàn bộ Script bao nhiêu lần:

  • Nhập 0 để chạy mãi (lặp vô hạn).
  • Nhập một số dương bất kỳ (1, 5, 100…) để chạy đúng bấy nhiêu lần.

Ví dụ: Script của bạn có 3 Step và bạn đặt số vòng lặp là 5, DeepTap sẽ chạy hết 3 Step, rồi quay lại từ Step 1, tổng cộng lặp 5 lần.

Menu của Script — đổi tên, nhân bản, xoá, post-loop

Chạm nút menu ⋮ bên cạnh dòng Script. Bạn sẽ thấy bốn lựa chọn (và Cancel):

  • Đổi tên — đặt cho Script một cái tên dễ nhớ (ví dụ "Bấm lặp", "Vuốt danh sách").
  • Nhân bản — tạo một bản sao y hệt với tên mới (ví dụ "Bấm lặp copy"). Rất tiện khi bạn muốn thử biến thể mà vẫn giữ nguyên bản gốc.
  • Edit post-loop — gắn một Process chạy mỗi vòng một lần, ở đầu vòng hoặc ở cuối vòng. Xem phần post-loop bên dưới.
  • Xoá — xoá hẳn Script. DeepTap không cho bạn xoá Script cuối cùng — lúc nào cũng phải còn ít nhất một cái.

Post-loop: chạy một Process mỗi vòng lặp

DeepTap có thể chạy một Process post-loop mỗi vòng một lần trong Script của bạn — bất kỳ Process nào đang bật Show in post-loop picker (ví dụ SIMPLE Close Popup Process có sẵn) để xử lý những thứ như popup.

Để thiết lập, chạm ⋮ > Edit post-loop. Hộp thoại Post-loop process mở ra:

  • Bật Run a process every loop.
  • Run at — chọn thời điểm chạy. Loop start (mặc định): trước Action đầu tiên của mỗi vòng, kể cả vòng 1 ngay sau khi bạn nhấn Play; sau vòng cuối thì không chạy thêm lần nào nữa. Loop end: sau Action cuối cùng của mỗi vòng. Cách nào thì mỗi vòng cũng chỉ chạy một lần. Chạm ? cạnh Run at để xem lời nhắc ngắn (× để ẩn đi).
  • Chọn Process trong danh sách — dấu ● đánh dấu cái đang chọn. Nếu danh sách trống, bạn sẽ thấy No eligible process. Create one first.
  • Chạm Save để lưu thay đổi.

Nâng cấp từ bản cũ? Những Script đã bật post-loop từ trước khi có Run at giờ sẽ chạy nó ở Loop start. Muốn giữ thời điểm như cũ, hãy mở Edit post-loop, chọn Loop end rồi chạm Save.

Khi một Process cho chạy lại vòng lặp (Reset): lượt chạy quay về vòng 1. Nếu chính Process post-loop trả về Reset khi chạy ở Loop start, các Action của vòng 1 sẽ chạy trước và Process chờ đến vòng sau — nhờ vậy một màn hình chưa kịp thay đổi không thể cứ reset mãi. Nếu Process nằm trong một Action cho chạy lại vòng lặp, vòng 1 mới vẫn bắt đầu bằng Process post-loop như thường (Loop start); còn với Loop end, vòng bị cắt ngang sẽ không có lượt chạy post-loop.

Ví dụ: Bạn có một Script lặp lại cùng một việc mỗi vòng, và thỉnh thoảng có popup che màn hình. Hãy bật post-loop và chọn một Process (ví dụ "SIMPLE Close Popup Process" có sẵn) — mỗi vòng DeepTap sẽ dẹp popup đó một lần rồi chạy tiếp, không làm phiền bạn.

Tab ⚙ CONFIG của View Script cũng có công tắc POST-LOOP và ô chọn Process, nhưng không có lựa chọn Run at — bật hay tắt ở đó vẫn giữ nguyên Run at mà bạn đã chọn ở đây.

Chép Script từ máy khác

Bạn có thể chép một Script từ một bản sao lưu — của chính bạn, bản gửi từ máy khác, hoặc bản mẫu có sẵn. Chạm ⧉ COPY trên thanh tiêu đề:

  1. Chọn nguồn — 📦 Sample (built-in), các bản sao lưu trên máy này (name (Local) · dd/mm hh:mm), hoặc ＋ Browse a backup file (Local) cho file mà ai đó chia sẻ với bạn. Ở các bản có máy chủ đồng bộ và đang bật PRO MODE, các bản sao lưu trên máy chủ cũng có trong danh sách. Chạm vào một nguồn để xem các Script của nó.
  2. Xem trạng thái — mỗi Script có một nhãn:
    • NEW — máy này chưa có Script đó; chạm Copy để thêm vào.
    • HAVE — bạn đã có Script này với Step và thiết lập y hệt; không cần chép nữa.
    • DIFF — bạn có Script trùng tên nhưng khác Step hoặc khác thiết lập (ví dụ khác số vòng lặp). Chạm Copy để ghi đè bản của bạn bằng bản ở máy kia.
  3. Xác nhận và chép — chạm Copy, xác nhận ở hộp thoại, và DeepTap chép Script về máy bạn (Script trùng tên sẽ bị ghi đè).

Script mang theo những gì nó cần. Nếu nó dùng Process hoặc Detector mà máy bạn chưa có — Process post-loop của nó (khi đang bật), một Process gắn vào một Action, một Run process nằm trong THEN, một Detector ở WHEN hoặc Detector của một Click button — DeepTap liệt kê chúng trong hộp thoại Copy dependencies too?. Copy all chép chúng cùng với Script; Cancel thì không chép gì cả. Những mục còn thiếu được tìm theo tên.

Mẹo: Chép Script rất tiện khi bạn đã thử xong trên một máy và muốn cài nhanh sang máy khác, hoặc khi bạn bè chia sẻ cho bạn một Script đã chạy tốt.

Bắt đầu và dừng chạy

Khi Script đã có Step, nhấn ▶ START để bắt đầu:

  • DeepTap hiện thanh công cụ nổi đè lên ứng dụng đó.
  • Nó chạy lần lượt hết các Step đang bật, rồi quay lại từ đầu nếu số vòng lặp lớn hơn 1.
  • Nếu post-loop đang bật, DeepTap chạy Process đã chọn mỗi vòng một lần — trước Action đầu tiên của vòng (Loop start) hoặc sau Action cuối cùng của vòng (Loop end).
  • Trong lúc chạy, nút play trên thanh công cụ biến thành một ô vuông màu đỏ. Chạm vào đó bất cứ lúc nào để dừng ngay.

DeepTap vẫn chạy ở nền — bạn có thể dùng ứng dụng khác hoặc bỏ điện thoại vào túi. Script vẫn tiếp tục chạy.

Cảnh báo: Đừng gỡ cài đặt DeepTap hay thu hồi quyền (Trợ năng hoặc Hiển thị đè) trong lúc Script đang chạy. Làm vậy có thể khiến máy bị khoá hoặc Script dừng bất ngờ. Nếu cần đổi thiết lập, hãy chạm ⏹ Stop trước đã.

Detector: nhận diện popup và màn hình

Một Detector dạy DeepTap cách nhận ra khi nào một popup hay một màn hình cụ thể xuất hiện trên điện thoại. Nó hoạt động bằng cách tìm các dấu hiệu hình ảnh (như nút "đóng" hoặc một biểu tượng đặc trưng) trong một vùng nhất định của màn hình. Nhận ra rồi, DeepTap có thể kích hoạt hành động hoặc nhảy sang bước tiếp theo trong Script của bạn.

Detector hoạt động ra sao

Mỗi Detector gồm ba phần:

  1. Các nút — những dấu hiệu hình ảnh bạn muốn tìm (như nút đóng popup hay nút cần bấm). Mỗi nút có một mã tên (ví dụ BTN_CLOSE) và một dòng mô tả.
  2. Luật nhận biết — những nút nào phải khớp thì Detector mới "báo". Chọn AND (phải tìm thấy tất cả các nút được đánh dấu) hoặc OR (chỉ cần thấy một nút được đánh dấu là đủ).
  3. Ngưỡng khớp — nút trên màn hình phải giống Template bạn đã chụp đến mức nào. Mặc định là 90% (0.90). Số càng cao thì càng khắt khe.
Template gắn với từng máy: khi bạn chụp một dấu hiệu hình ảnh (cắt nó ra từ màn hình), DeepTap lưu một ảnh PNG theo đúng độ phân giải của máy này. Nếu bạn chép một Detector từ máy khác về, Template của nó cũng được chép theo nên DeepTap khớp được ngay.

Detector mẫu (dữ liệu tạo sẵn, sửa được)

DeepTap không có Detector nào bị đóng cứng trong ứng dụng. Khi mới cài, nó tạo sẵn 4 Detector mẫu — chỉ là dữ liệu bình thường mà bạn sửa, chép hay xoá tuỳ ý (bản sao lưu 📦 Sample cũng mang theo chúng):

  • SIMPLE Popup1 và SIMPLE Popup2 — nhận ra một popup (dấu hiệu là BTN_POPUP1/BTN_POPUP2, cộng thêm nút cần bấm BTN_COLLECT).
  • ADVANCE Popup Close Button — nhận ra nút × dùng để đóng popup, qua dấu hiệu BTN_CLOSE.
  • ADVANCE Popup Gone — nhận ra popup đã biến mất và bạn đã quay lại màn hình phía sau nó (dấu hiệu BTN_GONE).

Đây là những Detector mà các Process đóng popup SIMPLE/ADVANCE có sẵn đang dùng. Bạn cũng có thể chép Region và Template của một Detector mẫu từ máy khác về để khỏi phải cắt lại trên máy này.

Tạo hoặc sửa một Detector

Mở tab DETECTORS ở đáy ứng dụng để quản lý các Detector (cái mới nhất nằm trên cùng):

  1. Chạm + NEW để tạo Detector mới, hoặc chạm vào tên một Detector có sẵn để sửa.
  2. Nhập tên Detector và đặt Threshold (%) — thường để 90 là ổn. Số thấp hơn (ví dụ 70) sẽ dễ dãi hơn nếu nút mỗi lần trông một khác; số cao hơn (95 trở lên) thì khắt khe hơn.
  3. Chọn luật nhận biết: AND hoặc OR.
  4. Ở mục BUTTONS, chạm + Add button để thêm từng dấu hiệu hình ảnh mà bạn muốn tìm.
    • Nhập mã nút (ví dụ BTN_CLOSE, BTN_TARGET).
    • Ghi thêm mô tả (nút này là nút gì?).
    • Tích identifier ở những nút quyết định việc Detector có báo hay không (kết hợp theo luật AND / OR). Nút không tích chỉ là chỗ để bấm. Phải tích ít nhất một nút.
    • Chọn các cách so của nút, tức match methods (tried in order, tick at least 1) — xem bảng bên dưới. Chạm ? cạnh ô tích bất kỳ để xem giải thích ngắn.
  5. Chạm SAVE.
Đổi tên mã của một nút? DeepTap tự động giữ đồng bộ ô tích identifier — nếu bạn đổi tên một nút đang được tích identifier, nó vẫn giữ nguyên dấu tích.

Cách so: NCC, MASKED, SHAPE

Mỗi nút có thể được so theo tối đa ba cách. Chỉ những cách được tích mới chạy, theo đúng thứ tự này, và cách nào đạt ngưỡng của Detector trước thì thắng. Nút mới tạo chỉ tích sẵn NCC.

Cắt một Template (Region)

Sau khi lưu Detector, bạn phải chụp một Template thì DeepTap mới biết cần tìm cái gì. Việc này làm trên thanh công cụ nổi, ngay trên ứng dụng bạn đang tự động hoá:

  1. Mở menu của thanh công cụ → List Detector rồi chạm tên Detector. Bảng của nó, Current Detector, liệt kê các nút của Detector cùng các Region của chúng (Region mới nhất nằm trên cùng).
  2. Ở một nút, chạm ＋ Add. Một Region nhỏ (15 × 15 px) hiện ra giữa màn hình: một khung viền đứt nét màu cam có nhãn NN · BUTTON, nối với một núm nằm bên dưới.
  3. Dời và chỉnh kích thước khung sao cho ôm trọn nút hoặc dấu hiệu bạn muốn chụp:
    • Kéo núm. Khi LOCK bật (núm xanh lá có 🔒, mặc định) thì cả khung đi theo; khi LOCK tắt (núm màu cam có số) thì chỉ riêng núm di chuyển.
    • Chạm vào núm, hoặc vào #NN của Region trong Current Detector, để mở bảng Region: thanh trượt WIDTH / HEIGHT (tối đa 300 px) và nút − / + để chỉnh kích thước, các mũi tên MOVE ±1 để dịch từng 1 px một.
  4. Chạm Crop để chụp lại vùng đó và lưu thành Template của bạn (ảnh hiện ở mục TEMPLATE). Sau đó chạm Save.

Bảng Region còn có con mắt (hiện hoặc ẩn Region này trên màn hình — Region bị ẩn vẫn được dùng để khớp), chip OK / Not Ready để đánh dấu những Region bạn đã làm xong (không ảnh hưởng đến việc khớp), PRIORITY: NORMAL / HIGH (Region HIGH được kiểm tra trước), ◈ TEST và ◉ CLICK. Thay đổi có hiệu lực ngay khi bạn chỉnh — bấm Cancel cũng không hoàn tác được. Chỉ những Region đã crop mới được dùng để khớp.

Trong Current Detector, các chip ở trên cùng dùng để lọc danh sách (Visible, Ready, Priority — chạm để đổi lần lượt). Mỗi dòng Region có HIGH / norm, Visible / Hidden, OK / Not Ready, Reset (đưa Region về giữa màn hình, giữ nguyên kích thước) và × (xoá).

Giờ Template đã được lưu trên máy cho nút này của Detector. Khi chạy, DeepTap sẽ đối chiếu đúng tấm ảnh đó trong lúc quét màn hình.

Một nút, nhiều Region? Bạn có thể thêm nhiều vùng cắt cho cùng một nút (hữu ích khi nút xuất hiện ở những chỗ khác nhau trên các màn hình khác nhau). DeepTap kiểm tra các Region ưu tiên HIGH trước, rồi đến các Region còn lại theo thứ tự, và bấm vào chỗ khớp đầu tiên.

Kiểm tra và dọn Region

  • View regions — ở tab DETECTORS, chạm biểu tượng hình ảnh trên dòng của một Detector. Bạn sẽ thấy mọi Region của mọi nút kèm ảnh đã crop, số thứ tự #NN, OK / Not Ready, và các cờ như no crop, hidden hoặc high. Màn này chỉ để xem, không sửa được.
  • ⌫ CLEAN (trên thanh tiêu đề của tab DETECTORS) — quét mọi Detector và đề nghị xoá những Region chưa từng được crop (chúng không bao giờ khớp được) cùng những Region trùng nhau (cùng chỗ, cùng ảnh). Nó cho biết số lượng và hỏi trước; thao tác này không hoàn tác được. Chip CLEAN trong Current Detector làm việc tương tự cho riêng Detector đó.

Ý nghĩa các nhãn

Khi bạn chép một Detector từ máy khác, bảng chọn hiện một nhãn bên cạnh mỗi Detector:

  • NEW (xanh lá) — máy này chưa có Detector đó.
  • HAVE (xám) — bạn đã có một Detector trùng tên và trùng cấu hình (nút, luật, ngưỡng).
  • DIFF (cam) — bạn có Detector trùng tên nhưng cấu hình khác (khác nút hoặc khác luật).

Dùng Detector của bạn

Khi đã có một Detector kèm Template đã cắt, bạn có thể dùng nó:

  • Làm điều kiện cho một Action: mở một Action chạm hoặc vuốt, sang tab RULE, bật ADVANCED rồi chọn Detector của bạn ở WHEN (condition). Action chỉ chạy khi Detector này khớp (hoặc, nếu bật Invert, chỉ chạy khi nó không khớp).
  • Trong luật của một Process động: dùng Detector ở điều kiện WHEN hoặc làm đích cho hành động ClickButton.
  • Trong lớp phủ Detector: soi và chỉnh Region ngay tại chỗ trong lúc chạy thử.

Hiểu về Process trong DeepTap

Một Process trong DeepTap là một bộ ra quyết định thu nhỏ. Nó có thể chạy mỗi vòng một lần với vai trò Process post-loop của một Script, chạy bên trong luật của một Action, hoặc được một Process khác gọi. Bạn cứ hình dung nó là một loạt luật kiểu "nếu xảy ra chuyện này thì làm việc kia", được DeepTap kiểm tra lần lượt. Luật nào khớp trước thì thắng, các luật còn lại bị bỏ qua.

Dùng Process để làm gì?

Process xử lý những tình huống bất ngờ xảy ra trong lúc chạy:

  • Đóng một popup hiện ra sau một thao tác
  • Xử lý các thông báo hay hộp thoại
  • Quyết định khi nào nên dừng hoặc chạy lại Script từ đầu
  • Đổi hướng hành động của DeepTap tuỳ theo thứ đang hiện trên màn hình

Process hoạt động ra sao: WHEN → THEN → OUTCOME

Mỗi luật trong một Process gồm ba phần:

Phần Làm nhiệm vụ gì Ví dụ
WHEN (điều kiện) Một phép kiểm tra mà DeepTap thực hiện trên màn hình. Nếu khớp, luật sẽ chạy. "Nếu nút đóng popup xuất hiện" hoặc "Nếu pin tụt dưới 20%"
THEN (hành động) Một hoặc nhiều việc DeepTap làm lần lượt khi điều kiện khớp Chờ 500ms, rồi bấm nút đóng
OUTCOME (điều khiển luồng) DeepTap làm gì sau khi các hành động xong Tiếp tục lặp, quay lại từ đầu, hoặc dừng Script

WHEN: các điều kiện

DeepTap đối chiếu điều kiện với những gì đang hiện trên màn hình:

  • Always — Điều kiện này luôn khớp. Rất hợp để làm luật dự phòng đặt ở cuối Process, hứng những trường hợp mà không luật nào bắt được.
  • Detector khớp — DeepTap tìm một Detector theo tên (một vùng bạn đã dạy nó nhận ra, ví dụ "popup_close_button"). Bạn chọn được bất kỳ Detector nào bạn đã tạo ở phần Detector.
  • Invert — Bật lên để đảo ngược điều kiện. Ví dụ "nếu popup_close_button KHÔNG xuất hiện" thay vì "nếu nó xuất hiện".
  • Mức pin — DeepTap kiểm tra pin máy và kích hoạt nếu pin thấp hơn hoặc cao hơn mức phần trăm bạn chọn (mặc định 20%).
Điều kiện hoạt động thế nào: Một điều kiện chỉ có khớp hoặc không khớp. Nếu khớp, DeepTap chạy các hành động THEN rồi làm theo OUTCOME. Nếu không khớp, DeepTap bỏ qua hẳn luật này và xét luật kế tiếp.

THEN: các hành động

Khi điều kiện khớp, DeepTap chạy lần lượt các hành động, cái này xong đến cái kia:

  • Wait — Dừng lại một số mili giây (1000 ms = 1 giây). Hữu ích để chờ hiệu ứng chạy xong rồi mới bấm.
  • Click button — Bấm một nút cụ thể thuộc Detector trong điều kiện WHEN. Khi bạn chọn "Click button", DeepTap hiện danh sách các nút có trong Detector đó; bạn chọn nút cần bấm.
  • Send Back — Bấm nút Back của máy một hoặc nhiều lần. Hữu ích để tắt hộp thoại.
  • Send Home — Bấm nút Home, quay về màn hình chính.
  • Send Recents — Bấm nút Recents (màn hình các ứng dụng gần đây).
  • Scroll — Cuộn màn hình theo hướng bạn chọn.
  • Send Text — Gõ một đoạn chữ vào ô nhập đang được chọn.
  • Send Enter — Bấm Enter trong ô nhập đang được chọn (Android 11 trở lên).
  • Capture — Lưu một ảnh chụp màn hình vào máy (xem lại ở CONFIG → General → SCREENSHOTS → VIEW).
  • Notify Discord — Gửi một tin nhắn tới Discord webhook của riêng bạn (CONFIG → Advance → DISCORD NOTIFY).
  • Perform action (caller) — Thực hiện cú chạm hoặc vuốt của chính Action có luật đã khởi chạy Process này. Trong tab RULE của Action, nó có tên Do this action.
  • Lock Screen — Khoá máy ngay lập tức (Android 9 trở lên).
  • Run Process — Gọi một Process khác chạy lồng vào, như một Script con. Process đó chạy xong thì quyền điều khiển trả lại cho Process hiện tại. Nếu Process lồng kết thúc bằng Stop hoặc Reset, kết quả đó cũng cắt ngang luôn Process cha.
Thứ tự hành động rất quan trọng: DeepTap chạy các hành động đúng theo thứ tự bạn xếp. Nếu bạn để chờ 2 giây rồi mới bấm, DeepTap sẽ chờ trước rồi mới bấm. Đảo thứ tự lại thì kết quả về thời gian cũng đổi theo.

OUTCOME: chuyện gì xảy ra tiếp theo

Sau khi mọi hành động xong, OUTCOME cho bộ máy chạy biết phải làm gì:

  • Continue — Vào ngay vòng lặp kế tiếp. Dùng khi bạn đã xử lý xong tình huống và muốn DeepTap tiếp tục công việc bình thường.
  • Next Step — Nhảy tới Step kế tiếp trong Process này. DeepTap quét lại màn hình và xét điều kiện của Step đó.
  • Go to Step N — Nhảy tới một Step cụ thể, trước hoặc sau đều được. DeepTap quét lại và xét điều kiện của Step đó. Rất tiện để tạo vòng lặp: một Step có thể nhảy về chính nó cho tới khi điều kiện thay đổi.
  • Reset — Chạy lại vòng lặp chính từ đầu. Hữu ích khi màn hình đã thay đổi nhiều.
  • Stop — Kết thúc lượt chạy. Bộ máy dừng lại và về trạng thái nghỉ.
  • Chain → [tên Process] — Chạy một Process khác sau khi Process này xong. Khi chọn OUTCOME này, bạn chỉ định Process cần chạy tiếp. Kiểu dùng phổ biến: xong một Process thì nối sang "ADVANCE Close Popup Process".

Tạo và sửa một Process

Trong màn hình Processes:

  1. Chạm + New để tạo Process mới, hoặc chạm tên một Process có sẵn để sửa.
  2. Đặt tên cho Process (ví dụ "Xử lý popup").
  3. Bật Show in post-loop picker nếu bạn muốn gắn Process này vào một Script làm Process post-loop của nó (khi đó nó chạy mỗi vòng một lần). Để tắt nếu Process này chỉ nên chạy khi được Process khác gọi qua OUTCOME Chain hoặc hành động Run Process.
  4. Đặt Max Duration (minutes) — thời gian tối đa Process này được phép chạy. Quá thời gian đó, DeepTap dừng nó lại và trả về Continue. Mặc định là 10 phút. Thiết lập này giúp tránh vòng lặp vô tận.
  5. Chạm + Add Step để thêm một luật (một Step) mới.
  6. Chạm vào một Step để mở rộng và sửa WHEN, THEN và OUTCOME.
  7. Đổi thứ tự các Step bằng nút mũi tên lên/xuống.
  8. Xong thì chạm Save.

Step không khớp thì sao

Nếu điều kiện của một Step không khớp, DeepTap bỏ qua các hành động của Step đó, không chạy chúng, và chuyển sang Step kế tiếp. Nhờ vậy mọi thứ chạy rất gọn: chỉ Step khớp đầu tiên được chạy, còn lại đều bị bỏ qua.

Hai Process mẫu có sẵn: SIMPLE & ADVANCE Close Popup

DeepTap tạo sẵn hai Process mẫu sửa được, minh hoạ trọn vẹn cách hệ thống Detector→Process vận hành. Chúng chỉ là dữ liệu bình thường — bạn có thể sửa, chép hoặc xoá, và bản sao lưu 📦 Sample cũng mang theo chúng. Cả hai đều bật Show in post-loop picker, nên cái nào cũng gắn được làm Process post-loop cho một Script.

SIMPLE Close Popup Process — mỗi popup một Step: WHEN Detector SIMPLE Popup1 (hoặc SIMPLE Popup2) khớp → bấm nút BTN_COLLECT của nó → Run Process → ADVANCE Close Popup Process để dẹp popup hiện ra sau đó.

ADVANCE Close Popup Process — một vòng lặp sáu Step dò tìm nút đóng (×) của popup:

  • Step 1–2: Detector ADVANCE Popup Gone phải khớp hai lần thì Process mới kết thúc: lần thấy đầu tiên chỉ để "lên nòng", sau đó nó chờ 3 giây rồi kiểm tra lại; lần thấy thứ hai chờ thêm 2 giây rồi trả về Continue.
  • Step 3: chừng nào chưa xác nhận được popup đã "biến mất", nó bấm Back hai lần, cách nhau 200 ms, rồi quét lại.
  • Step 4–5: Detector ADVANCE Popup Close Button (nút ×) — cứ mỗi lần thấy thứ 3, nó bấm Back trước rồi quét lại; nếu nút × vẫn còn đó thì nó bấm BTN_CLOSE, chờ 3 giây rồi bắt đầu lại từ đầu.
  • Step 6: không tìm thấy gì — nó chờ 3 giây rồi bắt đầu lại từ đầu.
  • Thời gian tối đa 180 giây — đến lúc đó mà popup vẫn chưa mất thì nó chạy ADVANCE Popup Timeout: chụp màn hình, gửi thông báo Discord và dừng Script.

Máy mới cài sẽ có ngay phiên bản này. Máy đã cài từ trước vẫn giữ bản cũ của nó cho tới khi bạn chép lại Process này từ 📦 Sample (built-in).

Hãy dùng chúng làm khuôn mẫu cho các luồng "phát hiện rồi hành động" của riêng bạn: từ Process nào cần dẹp popup sau khi thao tác, bạn nối (chain) sang Process ADVANCE, hoặc chép một trong hai cái rồi sửa lại theo ý mình.

Chép một Process từ máy khác

Bạn có thể chép một Process từ một bản sao lưu — của chính bạn, một file gửi từ máy khác, hoặc 📦 Sample có sẵn (ở các bản có máy chủ đồng bộ và đang bật PRO MODE thì có cả các bản sao lưu trên máy chủ):

  1. Trong danh sách Processes, chạm ⧉ COPY.
  2. Chọn nguồn có Process mà bạn muốn chép.
  3. DeepTap soi Process bạn chọn để tìm những thứ nó phụ thuộc vào — các Detector hoặc Process con mà nó gọi đến.
  4. Mỗi Process có một nhãn cho biết trạng thái:
    • NEW (xanh lá) — Máy bạn chưa có Process này. DeepTap sẽ chép về.
    • DIFF (cam) — Máy bạn có Process trùng tên nhưng nội dung khác. DeepTap sẽ hỏi bạn có ghi đè không.
    • HAVE (xám) — Máy bạn đã có Process này và giống hệt. Không cần chép.
  5. Chạm Copy. Nếu Process cần những Detector hoặc Process con mà bạn chưa có, DeepTap sẽ đề nghị chép luôn cả chùm đó. Cách này thường nhanh hơn nhiều so với ngồi dựng lại bằng tay.

Process lồng nhau qua Run Process

Một Process có thể gọi Process khác bằng hành động Run Process. Có giới hạn độ sâu để tránh gọi lồng vô tận, và mỗi Process có giới hạn Max Duration riêng cho từng lần được gọi. Khi một Process lồng trả về Stop hoặc Reset, kết quả đó được đẩy ngay lên Process cha.

Dùng một Process làm móc post-loop

Nếu một Process đang bật Show in post-loop picker, bạn có thể gắn nó vào một Script: HOME → ⋮ của Script → Edit post-loop (xem mục post-loop trong phần Script). Khi đó nó chạy mỗi vòng một lần — ở đầu vòng (mặc định) hoặc ở cuối vòng. OUTCOME của Process sẽ quyết định vòng lặp tiếp tục, chạy lại từ đầu hay dừng hẳn.

Sắp xếp Process cho gọn: Hãy giữ Process đơn giản. Một Process 3–5 Step dễ dò lỗi hơn nhiều so với cái 20 Step. Nếu thấy mình lồng quá nhiều tầng, hãy nghĩ đến việc tách phần logic phức tạp thành vài Process nhỏ nối tiếp nhau.

Thời gian tối đa mặc định

Thời gian tối đa mặc định cho một Process mới là 10 phút (600.000 mili giây). Bạn có thể giảm xuống nếu lo bị lặp vô tận, hoặc tăng lên nếu Process của bạn thật sự cần chạy lâu hơn. Đặt bằng 0 để tắt hẳn giới hạn thời gian (không giới hạn).

Trợ lý AI — dựng Process bằng ChatGPT

Ở màn hình PROCESSES có một nút AI nổi, mở ra Trợ lý AI — công cụ cho phép một chatbot AI (ví dụ ChatGPT) thiết kế hoặc chỉnh sửa Process và Detector giúp bạn. Bạn chỉ cần mô tả mong muốn bằng lời lẽ bình thường, bằng ngôn ngữ nào cũng được, rồi dán câu trả lời của AI trở lại DeepTap:

  1. COPY FOR AI — chép vào bộ nhớ tạm một đoạn hướng dẫn kèm các Process hiện có và cấu trúc Detector của bạn.
  2. Dán vào ChatGPT — dán nội dung đó vào bất kỳ khung chat AI nào và mô tả việc tự động hoá bạn muốn.
  3. Dán câu trả lời về + CHECK — DeepTap kiểm tra id, các tham chiếu và cấu trúc, rồi hiện bản tóm tắt những gì sắp thay đổi.
  4. APPLY — DeepTap tự lưu một bản sao lưu an toàn trước, sau đó hoà các thay đổi vào theo id.

🐞 DEBUG BUNDLE FOR AI (nằm dưới COPY FOR AI) dành cho lúc có gì trục trặc: nó gom tất cả trong một lần — Script, Process, Detector, ảnh Region và nhật ký chạy — để AI dựng lại đúng những gì đã diễn ra theo từng bước. Gói khoảng 512 KB trở xuống được chép vào bộ nhớ tạm; gói lớn hơn sẽ mở khung chia sẻ để gửi dưới dạng file. Nhật ký chạy lấy từ DETAIL LOG (bật sẵn theo mặc định); nếu nó đang tắt, hãy bật lên, làm lại lỗi đó một lần rồi xuất lại.

Vì việc hoà dữ liệu dựa trên id nên mục đang có sẽ được cập nhật tại chỗ, mục mới thì được thêm vào — không đụng đến thứ gì khác. Detector mới tạo chưa có Region nào: bạn hãy mở từng cái trong Current Detector, chạm ＋ Add, đặt khung trùm lên đúng nút thật rồi Crop một Template trước khi chạy. Nếu sau khi APPLY thấy có gì đó không ổn, hãy khôi phục bản sao lưu an toàn.

Thời gian và hiệu năng: cho DeepTap chạy nhanh (hoặc kiên nhẫn hơn)

DeepTap có năm thiết lập thời gian trong CONFIG → Advance → TIMING. Mục này được thu gọn sẵn — chạm SHOW để mở ra (mỗi lần bạn mở lại Config, nó lại thu gọn). Chúng quyết định một cú chạm được giữ bao lâu, DeepTap quét màn hình nhanh đến đâu, chờ bao lâu rồi mới bấm, và mỗi lần quét tốn bao nhiêu bộ nhớ. Mỗi ô đều có một nút ? kèm giải thích ngắn.

Vì sao chúng quan trọng

SCAN INTERVAL là mức sàn cứng do lớp Trợ năng của Android áp đặt. Nếu bạn chụp hai ảnh màn hình liên tiếp cách nhau dưới 333ms — chuyện này xảy ra khi một Process con chạy trong Process cha, hoặc khi DeepTap kiểm tra lại màn hình lần nữa — thì ảnh thứ hai lặng lẽ thất bại và không trả về gì cả. Trước khi hiểu ra vấn đề, người ta từng đổ oan cho công tắc Slow-Log cũ (nay đã được thay bằng DETAIL LOG): khoảng dừng ~1 giây của nó vô tình giãn hai lần chụp ra đủ xa nên mọi thứ chạy được. Giờ thì SCAN INTERVAL tự lo chuyện đó. Đừng đặt dưới 333ms; Android cũng sẽ bỏ qua thôi.

CLICK DELAY là khoảng nghỉ giữa lúc DeepTap phát hiện ra một nút và lúc nó bấm xuống. Khoảng nghỉ này cần thiết vì:

  • Nút vừa hiện ra có thể vẫn đang chạy hiệu ứng và chưa bấm được.
  • Một cú bấm bắn ra ngay sau khi chụp màn hình có thể bị hệ thống huỷ.

Đặt bằng 0 để tắt. Trên máy nhanh, bạn có thể hạ xuống 100–200ms. Trên máy chậm, hãy nâng lên 1000ms hoặc hơn.

CLICK HOLD chủ yếu quan trọng trên máy ảo: nếu cú chạm quá ngắn, một số máy ảo chỉ làm nút sáng lên mà không tính là đã click. Hãy nâng nó lên (ví dụ 100–200 ms) nếu các cú chạm từ Process làm nút sáng lên nhưng chẳng có gì xảy ra.

RE-SCAN AFTER xử lý một vấn đề khá tinh vi: nếu một Process ở lì trong cùng một Step khá lâu (ví dụ một lệnh Wait dài hoặc một Process con cứ dò đi dò lại), thì ảnh màn hình chụp lúc đầu đã "cũ" mất rồi. Đến lúc bấm thì màn hình có thể đã đổi. Khi đó DeepTap sẽ chụp lại và kiểm tra lần nữa; nếu nút đã dời chỗ hoặc biến mất, nó bỏ qua cú bấm cho an toàn thay vì bấm vào một cái bóng. Đặt bằng 0 để tắt và luôn dùng ảnh chụp ban đầu. Tối thiểu là 500ms (thấp hơn nữa thì Android cũng chặn lại).

MATCH RESOLUTION thu nhỏ ảnh chụp trước khi đem so với các mẫu đã lưu. Một tấm ảnh toàn màn hình trên điện thoại đời mới nặng khoảng 13 MB và bị giữ trong bộ nhớ suốt lượt quét. Trên máy ít RAM, chuyện này gây giật và treo khi máy dọn bộ nhớ. Bằng cách giới hạn cạnh dài nhất xuống, chẳng hạn 1600 pixel, DeepTap bỏ ngay bản ảnh gốc và chỉ giữ bản nhỏ. Vì DeepTap dù sao cũng thu mọi Region về 64×64 để đối chiếu, nên thu nhỏ vừa phải gần như không ảnh hưởng độ chính xác. Mặc định là 0 — giữ nguyên độ phân giải, không thu nhỏ; chỉ nên đặt giới hạn pixel (ví dụ 1600) nếu máy ít RAM bị giật hoặc treo. Chỉ những màn hình lớn hơn mức giới hạn mới bị thu nhỏ; màn hình nhỏ hơn giữ nguyên.

Khi nào nên chỉnh những thứ này:
  • DeepTap hay bỏ sót nút hoặc không bao giờ chạy Process lồng nhau: Nâng SCAN INTERVAL lên 400–600ms hoặc cao hơn (một số phiên bản Android bắt buộc khoảng cách dài hơn 333ms). Đồng thời kiểm tra MATCH RESOLUTION đang để 0 (độ phân giải gốc) để các nút nhỏ giữ được chi tiết.
  • Bấm không ăn hoặc bấm sai chỗ: Nâng CLICK DELAY lên 800–1500ms để nút kịp đứng yên rồi DeepTap mới bấm.
  • Nút sáng lên nhưng cú chạm không có tác dụng (hay gặp trên máy ảo): Nâng CLICK HOLD lên 100–200ms.
  • Máy nóng hoặc chậm dần khi chạy Script dài: Đặt giới hạn MATCH RESOLUTION để tiết kiệm RAM — thử 1600 trước, rồi 1200; đừng xuống dưới 480 kẻo biểu tượng nhỏ bị nhoè quá.
  • DeepTap chộp đúng lúc màn hình đang chạy hiệu ứng và bấm nhầm thứ khác: Nâng RE-SCAN AFTER lên 5000–10000ms để ảnh cũ sớm kích hoạt một lần chụp mới.

Dải thông số hệ thống

Bật SHOW SYSTEM STATS (CONFIG → Advance → LOG) để thấy chỉ số RAM và pin trong lúc DeepTap chạy. Nhờ đó bạn biết ngay theo thời gian thực một thay đổi thiết lập (nhất là MATCH RESOLUTION) có giúp giảm bộ nhớ hay không. Nếu thấy RAM trống tụt xuống hoặc pin hao vọt lên, đó là dấu hiệu bạn nên đặt giới hạn MATCH RESOLUTION (hoặc hạ mức giới hạn đang có xuống thấp hơn).

Quan trọng: Các thiết lập thời gian được áp dụng khi bạn nhấn SAVE ở cuối màn hình Config (sau đó Config tự đóng lại). Thay đổi có hiệu lực ngay; bạn không cần khởi động lại DeepTap hay ứng dụng nào cả.

Ảnh chụp màn hình & nhật ký

SCREENSHOTS nằm ở tab General của CONFIG: ảnh chụp chỉ được giữ ở trong máy — chạm VIEW để xem lại các ảnh đã lưu. Tab Advance có phần LOG — LIVE LOG (mặc định tắt: thông báo của Process và Detector trên dải chữ của thanh công cụ), DETAIL LOG (mặc định bật: nhật ký từng bước của bộ máy, dễ đọc, giữ lại 10.000 ký tự mới nhất; mở nó từ menu thanh công cụ → Log detail, có COPY và CLEAR) và SHOW SYSTEM STATS — cùng với DISCORD NOTIFY.

Lưu và thử lại

Sau khi chỉnh bất kỳ thiết lập thời gian nào:

  1. Chạm Save ở cuối màn hình Config.
  2. Đóng Config rồi chạy thử một Script hoặc thử chụp.
  3. Theo dõi nhật ký hoặc bật SHOW SYSTEM STATS để xem thay đổi có ăn thua không.
  4. Nếu chưa được, chỉnh tiếp rồi thử lại — bạn cứ thoải mái tinh chỉnh, chẳng mất gì cả.

Sao lưu & đồng bộ giữa các máy

DeepTap có thể sao lưu các cấu hình tự động hoá của bạn và chuyển chúng qua lại giữa điện thoại, máy tính bảng và máy ảo của bạn. Phần này giải thích về sao lưu, điểm khác nhau rất quan trọng giữa việc chép một mục với việc khôi phục toàn bộ, và — ở các bản có máy chủ đồng bộ — cách giữ cho Detector, Process và Script giống nhau trên mọi máy của bạn.

Có những phần nào là tuỳ vào phiên bản bạn dùng. Sao lưu trên máy (kèm một file trong thư mục Downloads), Share, ⧉ COPY và ↺ RESTORE từ một bản sao lưu trên máy thì bản nào cũng có. Mọi thứ cần đến máy chủ — sao lưu lên máy chủ, chép hoặc khôi phục từ bản sao lưu trên máy chủ, Merge, ⟳ SYNC ALL, ↑ UPLOAD / ↓ DOWNLOAD, CHECK và trang web quản trị — đều cần có máy chủ đồng bộ và phải bật PRO MODE (CONFIG → General). Bản Google Play không có máy chủ, nên các nút đó không bao giờ xuất hiện ở đó.

Sao lưu hoạt động thế nào

Mở CONFIG → General → BACKUP rồi chạm ⤴ BACKUP. Trong lúc làm việc, nút này hiện vòng xoay và phần trăm tiến độ. Bản sao lưu gồm:

  • Tất cả Script (chuỗi thao tác chạm/vuốt bạn đã ghi)
  • Tất cả Detector (các mẫu mà DeepTap học để nhận ra trên màn hình)
  • Tất cả Process (các luật và logic tự động hoá của bạn)
  • Các Region của nút (vị trí chính xác trên màn hình mà DeepTap bấm vào)
  • Các ảnh Template (ảnh cắt mà DeepTap dùng để tìm nút)

Bản sao lưu được lưu vào đâu là do BACKUP DESTINATION quyết định:

  • LOCAL — lưu trong ứng dụng và thành một file trong thư mục Downloads, DeepTap_USERNAME_date.txt (file cũ trùng tên sẽ bị thay). Đây là lựa chọn duy nhất ở bản Google Play, và cũng là lựa chọn duy nhất khi PRO MODE đang tắt.
  • SERVER (bản có máy chủ đồng bộ, đang bật PRO MODE) — tải lên tài khoản của bạn. Mọi máy dùng cùng một USERNAME thì dùng chung một bản sao lưu trên máy chủ này: lần sao lưu lên máy chủ nào cũng sẽ thay bản trước đó.

Share lưu một bản sao lưu mới kèm các Template của nó rồi mở khung chia sẻ của Android — gửi nó qua Gmail, Zalo, Messenger hoặc Drive sang máy khác, rồi ở máy đó lấy từng mục vào bằng ⧉ COPY → ＋ Browse a backup file (Local).

Đặt Username và Backup password

Cả hai ô đều nằm trong CONFIG → General → BACKUP. Máy chủ cần đủ cả hai — thiếu thì việc sao lưu, khôi phục và đồng bộ qua máy chủ đều bị từ chối. Sao lưu trên máy thì không cần ô nào cả.

  • USERNAME — tài khoản của bạn, đồng thời là sync hub (kho đồng bộ) mà Merge, Upload và Download đi qua. Dài 3–64 ký tự: chữ cái, chữ số và . _ + -. Lần đầu bạn dùng đến máy chủ, tên này sẽ được đăng ký, nên chỉ cần gõ sai một chữ là âm thầm tạo ra một tài khoản mới, trống trơn.
  • BACKUP PASSWORD — ít nhất 6 ký tự, được máy chủ kiểm tra để một máy khác dùng trùng tên tài khoản không ghi đè lên dữ liệu của bạn. Đây không phải mật khẩu đăng nhập.

Hãy dùng cùng một USERNAME và mật khẩu trên mọi máy của bạn — đó chính là thứ cho phép điện thoại khôi phục thứ mà máy tính bảng đã sao lưu, và giúp Merge, Upload, Download chạy được giữa các máy. Khi mới cài, USERNAME được điền sẵn bằng tên mẫu điện thoại kèm một con số (ví dụ 2412DPC0AG-6401) còn mật khẩu để trống: hãy đổi tên tài khoản thành cái tên bạn dễ nhận ra trước lần sao lưu lên máy chủ đầu tiên. ⤴ BACKUP và ↺ RESTORE dùng đúng những gì bạn đã gõ, kể cả khi bạn chưa nhấn SAVE.

Một máy không thấy bản sao lưu hoặc các mục đã đồng bộ của bạn? Hãy kiểm tra USERNAME và mật khẩu trên máy đó có giống các máy khác không — khác USERNAME là khác tài khoản.

Copy và Restore — khác nhau ở chỗ nào

DeepTap có hai cách rất khác nhau để lấy cấu hình từ một bản sao lưu — của bạn, bản gửi từ máy khác, hoặc 📦 Sample có sẵn. Bạn bắt buộc phải hiểu nên dùng cái nào:

Rất quan trọng: Restore là thao tác GHI ĐÈ. Nếu bạn khôi phục một bản sao lưu từ tuần trước, mọi thứ bạn thêm hoặc sửa từ đó đến nay sẽ MẤT SẠCH. Luôn sao lưu máy này TRƯỚC KHI khôi phục — sao lưu vào LOCAL (hoặc dùng Share): một bản sao lưu lên máy chủ làm ngay lúc này sẽ thay mất chính bản sao lưu trên máy chủ mà bạn đang muốn khôi phục.

Copy — chép từ một bản sao lưu (không phá dữ liệu)

Dùng ⧉ COPY để lấy an toàn một mục đơn lẻ mà không ảnh hưởng đến công sức của bạn. Nút này nằm trên thanh tiêu đề của từng danh sách: HOME (Script), PROCESSES và DETECTORS.

Chép được từ đâu: 📦 Sample (built-in); các bản sao lưu trên máy này (name (Local) · dd/mm hh:mm); ＋ Browse a backup file (Local) cho file mà ai đó chia sẻ với bạn; và, ở các bản có máy chủ đồng bộ và đang bật PRO MODE, bản sao lưu trên máy chủ của tài khoản bạn cùng các bản sao lưu được chia sẻ cho bạn.

Những gì được chép:

  • Với một Detector: mẫu nhận diện, toàn bộ Region của các nút, và ảnh Template của chúng
  • Với một Process: toàn bộ luật tự động hoá — kèm các Detector và Process con mà nó cần, nếu bạn đồng ý
  • Với một Script: chuỗi thao tác chạm/vuốt đã ghi — kèm các Process và Detector mà nó dùng, nếu bạn đồng ý

Cách nó xử lý khi trùng:

  • Mục trùng tên trên máy này sẽ bị thay — chỉ đúng mục đó
  • Mọi thứ khác của bạn vẫn y nguyên
  • Region giữ nguyên vị trí tính theo pixel; trên màn hình có độ phân giải khác, có thể bạn phải dời và crop lại chúng (xem bên dưới)

Từng bước (Script, Process và Detector đều làm giống nhau):

  1. Chạm ⧉ COPY trên thanh tiêu đề của danh sách
  2. Chọn nguồn
  3. Chạm vào mục bạn muốn — nhãn của nó ghi NEW, HAVE hoặc DIFF
  4. Nếu nó dùng Detector hoặc Process mà máy bạn chưa có, DeepTap liệt kê chúng trong hộp thoại Copy dependencies too? — chạm Copy all để chép kèm, hoặc Cancel để không chép gì cả
  5. Xác nhận việc chép — xong
Chép theo chùm: Process và Script mang theo những mục mà chúng phụ thuộc vào (tìm theo tên), nên không có gì bị trỏ tới một thứ mà máy này không có. Detector thì không có phần phụ thuộc nào phải mang theo.

Restore — khôi phục toàn bộ (ghi đè — nhớ sao lưu trước!)

Chỉ dùng ↺ RESTORE (CONFIG → General → BACKUP) khi bạn muốn thay sạch toàn bộ cấu hình của máy này bằng một bản sao lưu đầy đủ. Thường dùng khi:

  • Bạn vừa gỡ rồi cài lại DeepTap và muốn lấy lại cấu hình cũ
  • Bạn nhân bản nguyên trạng cài đặt từ máy này sang máy khác (và không cần giữ gì ở máy đích)

Restore làm những gì:

  • Thay toàn bộ Detector, Process và Script bằng bản có trong bản sao lưu
  • Thay sạch mọi Region của nút bằng Region trong bản sao lưu — Region bạn tự thêm sẽ bị xoá, kèm cả ảnh crop
  • Xoá mọi thứ trên máy bạn mà bản sao lưu không có

Trước khi bấm Restore:

  1. Đặt BACKUP DESTINATION là LOCAL rồi chạm ⤴ BACKUP để lưu lại cấu hình của máy này
  2. Kiểm tra xem có hiện Backed up to Local ✓ không
  3. Giờ bạn có thể yên tâm chạm ↺ RESTORE và chọn bản sao lưu trong Restore from… — nếu có gì sai, hãy khôi phục lại bản sao lưu local của bạn

Đồng bộ giữa các máy của bạn

Ở các bản có máy chủ đồng bộ và đang bật PRO MODE, tài khoản ứng với USERNAME của bạn hoạt động như một sync hub: mọi máy dùng cùng USERNAME và mật khẩu đều có thể gửi mục lên hub và lấy mục từ hub về, từng mục một, mà không phải khôi phục toàn bộ.

Merge — một Detector. Chạm Merge trên dòng của một Detector ở tab DETECTORS (nút này cũng có dưới tên Detector trong List Detector nổi, và trên thanh tiêu đề của Current Detector). DeepTap gộp Detector đó với hub, rồi tải kết quả lên:

  • Thiết lập của Detector — tên, các nút cùng ô tích identifier và các ô tích cách so, ngưỡng, luật: bản có version mới hơn thắng.
  • Region, theo id: bản có version mới hơn thắng, kèm ảnh của nó. Region chỉ hub có sẽ được thêm vào — trừ khi máy này đã xoá nó kể từ lần Merge trước. Region chỉ máy này có sẽ được giữ lại — trừ khi một máy khác đã xoá nó.
  • OK / Not Ready (của Detector, nút, Region) và Visible / Hidden của Region và nút: thay đổi gần nhất thắng.
  • Giữ riêng cho từng máy, không bao giờ đồng bộ: Detector nào đang hiện trên màn hình, LOCK và vị trí các núm.

Version chỉ thay đổi khi bạn lưu: Save trong bảng Region (Crop rồi Save), các chip OK / HIGH trong Current Detector, các công tắc hiện/ẩn, công tắc OK, và SAVE trong màn sửa Detector. Kéo, dịch hoặc đổi kích thước mà không Save thì chỉ nằm trên máy này và có thể bị một bản mới hơn từ hub thay thế. Kết quả trông như ✓ Merged "name": +2 new · 1 updated · 0 removed.

⟳ SYNC ALL — mọi Detector. Ở tab DETECTORS, ⟳ SYNC ALL trước hết tải về những Detector mà hub có còn máy này chưa có (kèm Region và ảnh của chúng), rồi lần lượt gộp từng Detector trên máy này, có cửa sổ hiện tiến độ. Máy mới chỉ cần một lần chạm là kéo về được tất cả. Nó dừng ngay nếu sai USERNAME hoặc mật khẩu, hoặc khi không có mạng; lỗi ở một Detector riêng lẻ sẽ được liệt kê ở cuối, các Detector khác vẫn chạy tiếp.

↑ UPLOAD / ↓ DOWNLOAD — một Process hoặc Script. Các nút này có trên từng dòng của tab PROCESSES và trên từng thẻ Script ở HOME. ↑ UPLOAD thay bản trên hub bằng bản của máy này; ↓ DOWNLOAD thay bản trên máy này bằng bản trên hub (bị từ chối nếu hub chưa có). Các mục được khớp theo id, không theo tên. Hộp thoại xác nhận cho biết bản trên hub được sửa lần cuối lúc nào, và bởi tài khoản nào. Những gì một mục cần sẽ đi cùng với nó: Detector mà phía bên kia chưa có sẽ được merge trước, Process con còn thiếu được chép theo; những cái phía bên kia đã có thì để nguyên, kể cả khi chúng khác nhau — hãy upload hoặc merge riêng những cái đó. Một Script mang theo Process post-loop của nó, các Process và đích Run process trong các Action của nó, và các Detector mà các Action của nó dùng.

Version, dấu “+” và CHECK. Sau tên của mỗi Script, Process và Detector, bạn thấy version của nó, ví dụ v30/09 21:05 — giờ trên máy chủ của lần Upload / Download gần nhất (Script, Process) hoặc lần Merge / Sync all gần nhất (Detector) — hoặc no version yet. Dấu + sau version nghĩa là máy này đã thay đổi nó kể từ đó: với Script và Process, nội dung khác với bản đã đồng bộ (sửa ngược lại đúng như cũ thì dấu + biến mất); với Detector, đã có thay đổi được lưu kể từ lần Merge gần nhất. CHECK hỏi hub rồi ghi thêm same version as hub, hub: v… · account (một máy khác đã đồng bộ một version khác) hoặc not in hub. Các kết quả này mất đi khi bạn chuyển tab. Detector chưa có version cần chạy ⟳ SYNC ALL một lần.

↑ UPLOAD ALL · ↓ DOWNLOAD ALL · CHECK ALL. Thanh phía trên danh sách HOME và PROCESSES chạy ↑ UPLOAD cho mọi mục trên máy này, hoặc ↓ DOWNLOAD cho mọi mục trên hub — thêm những mục máy này chưa có; mục chỉ có trên máy này thì giữ nguyên — lần lượt từng mục, có cửa sổ hiện tiến độ. Ở tab DETECTORS, thanh này là ⟳ SYNC ALL · CHECK ALL.

Các nút ALL không so version. ↑ UPLOAD ALL ghi đè lên một bản mới hơn mà máy khác vừa upload; ↓ DOWNLOAD ALL ghi đè lên những thay đổi local của bạn đang có dấu +. Hãy nhấn CHECK ALL trước để xem cái gì khác nhau.

Template và độ phân giải màn hình

Template của nút (những ảnh cắt mà DeepTap dùng để tìm và bấm nút) gắn chặt với độ phân giải màn hình máy bạn. Khi bạn chép hoặc merge một Detector từ máy khác:

  • Cùng độ phân giải: Template chép sang là dùng được ngay, khớp hoàn hảo
  • Khác độ phân giải: Region giữ nguyên vị trí tính theo pixel và Template giữ nguyên kích thước, nên có thể bị trượt — hãy dời Region và crop lại ngay trên máy này

Đó là lý do các máy có màn hình y hệt nhau (ví dụ cùng một mẫu máy ảo hoặc cùng một dòng điện thoại) là hợp nhất để chia sẻ cho nhau.

Truy cập bảng điều khiển web

Ở các bản có máy chủ đồng bộ, các bản sao lưu còn xem và quản lý được qua một trang web quản trị, do người vận hành máy chủ giữ. Trang đó có bảo vệ bằng đăng nhập, và địa chỉ của nó không còn là thứ bạn phải nhập trong app nữa. Từ đó có thể:

  • Xem tất cả bản sao lưu của các máy kèm thời điểm sao lưu
  • Xem trước các Detector, Process và Script
  • Sửa cấu hình trước khi nạp sang một máy khác

Vài cách dùng phổ biến

Cách 1: một tài khoản, nhiều máy

Dùng cùng một USERNAME và mật khẩu trên mọi máy. Cải tiến một cấu hình trên bất kỳ máy nào, rồi Merge Detector đó hoặc ↑ UPLOAD Process hay Script đó. Trên các máy còn lại, nhấn CHECK ALL để xem có gì thay đổi, rồi ⟳ SYNC ALL (Detector) và ↓ DOWNLOAD / ↓ DOWNLOAD ALL (Process, Script).

Cách 2: máy mới hoặc máy vừa cài lại

  1. Nhập cùng USERNAME và BACKUP PASSWORD như trên các máy khác của bạn
  2. Hoặc chạm ↺ RESTORE rồi chọn bản sao lưu của tài khoản bạn (thao tác này thay toàn bộ mọi thứ trên máy)…
  3. …hoặc giữ nguyên những gì đang có và kéo các mục đã đồng bộ về: ⟳ SYNC ALL ở DETECTORS, rồi ↓ DOWNLOAD ALL ở PROCESSES và ở HOME

Cách 3: thử nghiệm cấu hình mới

Bạn muốn thử một Process mới mà không làm hỏng bộ cài chính. Hãy dùng một máy thứ hai (hoặc máy ảo):

  1. Dùng ⧉ COPY để chép đúng những Detector bạn cần — ví dụ từ một file sao lưu mà bạn đã chia sẻ từ máy chính
  2. Thoải mái dựng và thử Process mới ở đó
  3. Khi đã chạy ngon, đưa nó về máy chính — bằng Share và ⧉ COPY, hoặc bằng ↑ UPLOAD ở máy này rồi ↓ DOWNLOAD ở máy kia
Nhớ nhé: ⧉ COPY là bạn thân khi bạn muốn chia sẻ từng phần nhỏ. Restore dành cho việc thay mới toàn bộ. Merge, Upload và Download giữ cho cùng các mục luôn khớp nhau trên mọi máy của bạn. Còn phân vân thì cứ sao lưu trước đã.

DeepTap 的运作原理

了解这款应用如何自动点击、如何识别屏幕内容、如何处理弹窗 —— 从核心概念一路讲到动手操作。

快速上手（约 5 分钟）

第一次用 DeepTap？先选一个级别 —— 后面的级别都建立在前一个之上。建议从 BASIC 开始；准备好了再回来看 ADVANCE 和 EXPERT。这三段视频在应用里也有，就在底部的 GUIDE 标签里。

大约五分钟，从零做出第一个能跑起来的自动点击 —— 不讲术语。

▶ 视频演示：授予两项权限，在 Sample 练习页上录制四个点击，设置循环次数，然后运行

💡 想找个安全的对象练手？切换到本页顶部的 🎮 Sample 标签，选 BASIC 模式，让它自动按下四个 +5 方块。

第 0 步 —— 一次性设置（权限）

DeepTap 需要两项 Android 权限才能替你点击；在 Android 13 及以上还需要第三项，好让你知道 Script 正在运行。这些权限都只需授予一次：只要还缺一项，主界面就会显示红色的 ⚠ PERMISSIONS REQUIRED 横幅，每个缺少的权限那一行都有一个 FIX NOW 按钮。

权限为什么需要在哪里开启
无障碍服务（Accessibility Service）让 DeepTap 代替你执行点击和滑动，并读取屏幕，与你裁剪的样图作比对。FIX NOW → I agree — open Settings → 无障碍 → DeepTap → 打开
显示在其他应用上层把悬浮控制条显示在你要自动化的那个应用之上。Android 设置 → 应用 → DeepTap → 显示在其他应用上层 → 允许
通知（Notifications）（Android 13 及以上）显示一条通知，告诉你有 Script 正在运行。点击功能本身不需要它。DeepTap 会自己询问一次。如果你当时拒绝了，点 FIX NOW 会再问一次——如果 Android 已不再弹出询问，则会打开 DeepTap 的通知设置。
在打开 Android 设置之前，DeepTap 会先显示 How DeepTap uses Accessibility：它代你点击和滑动；它读取屏幕，把一些小区域与你裁剪的样图作比对；这些数据都留在你的设备上。只有点 I agree — open Settings 才会进入设置。点 Not now（或按返回键）只会关闭这个说明；之后在 Script 上按 ▶ 时它会再次出现。
注意：没有无障碍服务，什么都点不了；没有悬浮窗权限，悬浮控制条不会出现。

DeepTap 的运作原理：核心概念

DeepTap 是一款 Android 自动点击工具：你可以录制手机屏幕上的点击和滑动并重放，让它们循环自动执行。但 DeepTap 更聪明一些 —— 它能观察屏幕上出现了什么，并据此决定下一步做什么，比如关掉一个弹窗，或者在按钮出现时点它。

要理解 DeepTap，你需要掌握四个核心概念：

1. Script：你录制的一串动作

Script（脚本）是你录制的一系列点击和滑动。每个 Action 都会连同它在屏幕上的精确坐标一起保存。按下 Play 后，DeepTap 会按你设定的循环次数反复执行这些动作。可以把它想成一个宏：点这里、划一下、再点一次。

  • Click：在屏幕上某个指定位置点一下
  • Sweep：从一个位置拖动到另一个位置
  • 循环次数：所有 Action 要跑多少轮（≥1）。设为 0 可以停用这个 Script 而不必删除它。

每个 Script 都有名字，可以包含很多 Action。你可以创建多个 Script 并在它们之间切换。

2. Detector：识别屏幕上有什么

Detector（检测器）是 DeepTap 用来识别屏幕上出现的东西的方式 —— 比如一个弹窗或一个关闭按钮。有了它，DeepTap 就不必盲目地反复点同一个位置，而是能看见屏幕上的内容并作出反应。

Detector 是怎么工作的？它把一张小的参考图（叫 Template，模板）与当前屏幕内容作比对，比对范围限定在某个特定区域（Region）内。如果两者足够相似，DeepTap 就知道那个东西出现了。例如：

举例：你想让 DeepTap 关掉一个弹窗。你把弹窗上的关闭按钮（那个 ×）截图裁剪下来，保存为 Template，再告诉 DeepTap 到屏幕的哪个位置去找它。每次扫描屏幕时，DeepTap 都会检查那个 Region 并与 Template 比对。一旦找到 × 按钮，它就知道弹窗打开了。

DeepTap 预置了 4 个可编辑的示例 Detector 供你参考学习（SIMPLE Popup1、SIMPLE Popup2、ADVANCE Popup Close Button、ADVANCE Popup Gone），你也可以自己创建更多。

3. Process：智能决策

Process（流程）是一个小型状态机，它借助 Detector 来决定该做什么，本质上就是一串 IF-THEN 规则。例如：

  • IF 检测到弹窗 THEN 点击目标按钮 THEN 关掉出现的弹窗 THEN 继续循环
  • IF 没有找到弹窗 THEN 重置循环计数，从头再来

Script 的每一轮循环中（默认是在这一轮的第一个 Action 之前），DeepTap 都可以运行一次 Process 来检查屏幕并作出决定：

  • Continue：继续循环
  • Reset：循环计数重新从 1 开始
  • Stop：结束播放

Process 就像菜谱：你把步骤写下来，DeepTap 每次都照着做。

4. Region + Template：去哪里找、要匹配什么

Region（区域）是屏幕上的一个矩形范围；Template（模板）是你要找的东西的一张小截图（PNG 图片）。两者合起来告诉 DeepTap："在这个矩形里看，把看到的画面和这张图作比对。"

Region 要扫描区域的位置 (x, y) 和尺寸（宽、高）
Template 你想找的目标的参考图（PNG）

扫描时，DeepTap 会计算 Template 与该 Region 内画面的相似度 —— 一个 0% 到 100% 的分数。分数达到该 Detector 的阈值（通常是 90%）就算匹配成功。

重要：Region 和 Template 都是跟具体设备绑定的。把应用换到另一台手机上，坐标很可能就不对了。Script 和 Process 可以在设备之间复制，但 Template 需要在新手机上重新截取。

两种模式：编辑模式与播放模式

模式一：编辑模式 —— 搭建你的 Script

打开 DeepTap 时，你处在编辑模式。在这里你可以：

  • 创建 Script 并为它命名
  • 点击悬浮控制条上的按钮来录制点击和滑动
  • 在屏幕上预览你的 Action（带可拖动的手柄和调节钮）
  • 设置循环次数和时间上限
  • 挂载一个每轮循环运行一次的 Process，可以在每轮开始或结束时运行（比如"按钮出现就点它，然后关掉弹窗"）

此时应用停留在前台，你会看到一个悬浮控制条，上面有添加 Action、查看 Script 和开始播放的按钮。

模式二：播放模式 —— 在后台自动点击

在某个 Script 上按下 ▶ START，DeepTap 就切换到播放模式：

  1. DeepTap 应用退到后台（这样你能看见被自动化的那个应用）
  2. 悬浮控制条留在最上层，此时显示播放/停止按钮和 DeepTap 当前动作的实时日志
  3. DeepTap 循环执行 Script 里的 Action，并在两轮之间扫描屏幕、检查各个 Detector
  4. 如果某个 Detector 匹配成功，就运行挂载的 Process（例如关掉弹窗、在按钮出现时点它）
  5. 按 ⏹ STOP 结束播放并回到编辑模式
你随时都能看到 DeepTap 在干什么：控制条上的日志条有两行。第 1 行是进度，例如 L6/10 A4 · 12s（共 10 轮中的第 6 轮、第 4 个 Action、已用 12 秒）。第 2 行是最新的消息：Process 的步骤、Detector 的命中、错误，以及播放停止的原因。只有打开 LIVE LOG（CONFIG → Advance）时，Process 和 Detector 的消息才会显示在这里。想看完整的逐步记录，就在控制条菜单里打开 Log detail —— DETAIL LOG 默认是开启的。出问题时，这些日志是第一个该看的地方。

悬浮控制条：你的控制中心

处于 Edit 或 Play 模式时，会有一个小控制条浮在其他应用之上。它包含：

  • Add Click / Add Sweep：录制一个新的 Action（仅在编辑模式可用）
  • ⚙ View Script：打开原生覆盖层，把所有 Action 以可拖动的卡片形式列出，并显示该 Script 的专属设置（循环次数、时间上限、低电量停止、结束后锁屏）
  • 菜单：List Detector / Current Detector（显示并编辑某个 Detector 的 Region）、List PROC（选择要测试的 Process）、Test PROC (name)（把该 Process 真实运行一次 —— 它会真的点击 —— 用来调试）以及 Log detail（逐步日志，仅在打开 DETAIL LOG 时出现）
  • ▶ / ⏹ Play / Stop：启动或停止播放循环
  • 实时日志条：运行时显示两行 —— 进度（例如 L1/5 A3 · 2s）和最新的消息（Process 的某一步、Detector 的命中、错误，或停止的原因）

一次典型的配置流程

第一次使用 DeepTap 时，可以这样配置：

  1. 创建 Script：点 HOME → + NEW
  2. 录制 Action：点悬浮控制条上的 Add Click 或 Add Sweep，然后在目标应用的画面上点击/拖动来放置这个 Action。重复操作，直到录完一个完整的"循环周期"（例如点某个按钮 5 次）。
  3. 设置循环次数：点 ⚙ View Script → 滚动到 LOOP COUNT → 填入要重复的次数（例如 10）。
  4. 创建 Detector（可选）：点 DETECTORS → + NEW。把你想识别的东西（比如弹窗上的按钮）截图裁剪下来，保存为 Template。
  5. 创建或选择一个 Process：点 PROCESSES → 选一个现成的，或者新建规则（例如"如果出现弹窗，就点目标按钮，然后关掉弹窗"）。
  6. 挂载 Process：回到 HOME → 点该 Script 的 ⋮ 菜单 → Edit post-loop → 打开开关，选择 Run at（Loop start 或 Loop end），再选择你的 Process。
  7. 测试：按 ▶ START，观察实时日志，让它跑几轮，然后按 ⏹ STOP。
  8. 调整：如果 Action 的位置不对，点 ⚙ View Script 修改每个 Action 的坐标；如果 Detector 匹配不上，去 DETECTORS 调整 Region 或 Template。
小技巧：如果检测或点击不够稳定，试着调整 CONFIG → Advance → TIMING（点 SHOW）里的 SCAN INTERVAL (ms) 和 CLICK DELAY (ms)。调试时可以从控制条菜单打开 Log detail，查看易读的逐步引擎日志（DETAIL LOG 默认开启）。

Script：创建和管理自动化序列

Script（脚本）就是 DeepTap 录制并在你手机上重放的一串点击和滑动。DeepTap 把你所有的 Script 集中在一个库里，方便你随时切换、修改和运行。

Script 列表（主界面）

打开 DeepTap 就能看到 Script 列表。每一行代表一个 Script，包含你需要的全部信息：

  • Script 名称 —— 点名称即可把它设为当前活动的 Script（也可以通过菜单设置）。
  • 概要信息 —— N actions · loop N；开启了 post-loop Process 时，后面还会用琥珀色显示 ⟳ process name。
  • Play 按钮 —— 点 ▶ 会把这个 Script 设为活动，并打开悬浮控制条。DeepTap 会把自己退到后台，这样你就能看到被自动化的那个应用；再按控制条上的 Play 才开始运行。
  • 菜单按钮 —— 点 ⋮（三个点）可以重命名、复制、删除该 Script，或编辑它的 post-loop 设置。

提示：带青色边框高亮、并带有 ● ACTIVE 标记的那一行就是当前活动的 Script —— 控制条播放的就是它。你可以有很多 Script，但同一时间只有一个是活动的。

最新的 Script 排在列表最上面。在带同步服务器的版本中（且已打开 PRO MODE），每张卡片还会在名称后面显示该 Script 的版本，以及 ↑ UPLOAD、↓ DOWNLOAD 和 CHECK 按钮；列表上方则有 ↑ UPLOAD ALL · ↓ DOWNLOAD ALL · CHECK ALL —— 详见 备份与同步。

新建一个 Script

点顶部的 + NEW。DeepTap 会创建一个名为 Script 2、Script 3 之类的 Script，把它放到列表最上面并设为活动。新建的 Script 是空的 —— 还没有任何 Step。点 ▶ 打开控制条，就可以开始添加 Step 了。

添加 Step（点击与滑动）

在某个 Script 上按下 ▶ 后，屏幕上会出现悬浮控制条。你可以在这里添加和播放 Step：

  • 添加点击 —— 点 ＋ Click，屏幕上会出现一个带编号的绿色手柄；把它拖到你想点击的准确位置。DeepTap 会把这个位置保存为绝对坐标。新的 Action 会加到 Script 的末尾。
  • 添加滑动 —— 点 ＋ Sweep，屏幕上会出现一个箭头，两端各有一个带编号的手柄：尾端是手指按下的位置，箭头那端（箭尖）是手指抬起的位置。拖动任意一个手柄可以移动那一端；按住箭头的线条拖动，则可以整体移动这次滑动，方向和长度都不变。
  • 删除一个 Step —— 点它的手柄，在面板里按 × Delete；或者在 View Script 里选中它的卡片，再点 🗑。

手柄平时是绿色的；Action 带有 WHEN 条件时变成紫色；Action 被停用时会变暗。Script 播放期间，手柄和箭头不响应触摸。

重要：Step 记录的是绝对屏幕坐标。如果你在一台 1080×2400 屏幕的手机上录制了位置 (500, 1000) 的点击，那么在任何设备上它都会去点 (500, 1000)，跟屏幕尺寸无关。把 Script 拿到另一台手机上跑，点击很可能会错位。换设备后请重新录制或编辑这些 Step。

整理和重排 Step

有两个地方可以查看和修改 Step。

View Script（控制条 ⚙ View Script → ◈ ACTIONS）把每个 Action 显示成一张带编号的卡片。点一张卡片可以看到它的详情 —— 按住时长或滑动速度、等待时间、Advanced: ON / off、它用到的 Process 和 Detector —— 以及下面这些按钮：

  • 🗑 删除 · 眼睛图标（显示或隐藏它的手柄）· ✎ EDIT（打开编辑面板）· ↑ UP / ↓ DOWN（上移或下移一位）。
  • ◎ RESET POSITION —— 把这个 Action 移回屏幕中央。手柄跑到屏幕外面时就用它；滑动会保持原来的方向和长度。
  • 会重复执行的 Action，标题后面会显示 ×N，例如 CLICK #03 ×3。

编辑面板（点手柄，或点 ✎ EDIT）有三个标签：

  • PARAMS —— WAITING (ms)：这个 Action 执行完之后、下一个开始之前的停顿。点击用 TIME HOLD (ms)，滑动用 SWEEP SPEED (ms)。REPEAT (times)：1 = 执行一次；3 = 动作 → 等待，连续 3 次。INDEX：填入位置 1…N，按 Save 后这个 Action 就会移到那里。Enabled：关闭 = 播放时跳过，但仍保留在 Script 里。
  • MOVE —— ORDER 配合 ▲ Up / ▼ Down。对滑动来说，POINT 的 ① Head / ② Tail 用来选择要移动哪一端（默认先选中 Head，也就是箭头那一端）。MOVE ±1：方向箭头每按一次微调 1 像素；也可以在中间的输入框里填 x,y（例如 540,1200）再按 Done —— 这个点会被限制在屏幕范围内。MOVE 标签里的改动会立即生效。
  • RULE —— 打开 ADVANCED，就能给这个 Action 设置它自己的规则：WHEN (condition)（None (always run) 或某个 Detector，可配合 Invert）、THEN (actions) 和 OUTCOME（Continue / Reset loop / Stop）。THEN 里的动作从上到下依次执行；用 ▲ / ▼ 调整顺序，用 ✕ 删除一个，用 + Add action 添加一个。每个动作的作用见 Process 一节。

循环次数 —— 要跑多少轮

打开 ⚙ View Script → ⚙ CONFIG，其中的 LOOP 输入框决定 DeepTap 把整个 Script 重复执行多少次：

  • 填 0 表示一直跑下去（无限循环）。
  • 填任意正数（1、5、100 等）表示正好跑这么多轮。

举例：如果你的 Script 有 3 个 Step，循环次数设为 5，DeepTap 会执行完这 3 个 Step，再从第 1 个 Step 重新开始，总共重复 5 轮。

Script 菜单 —— 重命名、复制、删除、Post-Loop

点某个 Script 行旁边的菜单按钮 ⋮，会看到四个选项（另外还有 Cancel）：

  • 重命名 —— 把 Script 改成一个好记的名字（例如 "Tap Loop"、"Spin Wheel"）。
  • 复制 —— 用新名字创建这个 Script 的完整副本（例如 "Tap Loop copy"）。适合在不破坏原版的前提下测试各种改动。
  • Edit post-loop —— 挂载一个每轮循环运行一次的 Process，在每轮开始或结束时运行。详见下面的 Post-Loop 一节。
  • 删除 —— 永久移除该 Script。DeepTap 不允许你删掉最后一个 Script —— 至少要保留一个。

Post-Loop：每轮循环运行一个 Process

DeepTap 可以在 Script 的每一轮循环中运行一次 post-loop Process —— 任何打开了 Show in post-loop picker 的 Process 都可以（例如内置的 SIMPLE Close Popup Process），用来处理弹窗之类的情况。

设置方法：点 ⋮ > Edit post-loop，会打开 Post-loop process 对话框：

  • 打开 Run a process every loop。
  • Run at —— 选择它什么时候运行。Loop start（默认）：在每一轮的第一个 Action 之前运行，包括按下 Play 后紧接着的第 1 轮；最后一轮结束后不会再运行。Loop end：在每一轮的最后一个 Action 之后运行。不管选哪个，每轮都只运行一次。点 Run at 旁边的 ? 可以看到简短说明（点 × 收起）。
  • 从列表中选择 Process —— 带 ● 的就是已选中的那个。如果列表是空的，会显示 No eligible process. Create one first.
  • 点 Save 保存修改。

从旧版本升级过来？在还没有 Run at 这个选项时就已开启 post-loop 的 Script，现在会在 Loop start 时运行它。想保持原来的时机，就打开 Edit post-loop，选择 Loop end，再点 Save。

当 Process 重置循环时：播放会回到第 1 轮。如果是 post-loop Process 本身在 Loop start 时返回 Reset，那么第 1 轮的 Action 会先执行，这个 Process 要等到下一轮才运行 —— 这样，还没来得及变化的屏幕就不会一直触发重置。如果是某个 Action 里的 Process 重置了循环，新的第 1 轮会照常先运行 post-loop Process（Loop start）；如果选的是 Loop end，被打断的那一轮就不会运行 post-loop。

举例：你有一个每轮重复某项任务的 Script，而屏幕偶尔会被弹窗挡住。启用 post-loop 并选一个 Process（例如内置的 "SIMPLE Close Popup Process"）—— DeepTap 就会在每轮循环中清理一次那个弹窗，然后继续运行，完全不用你插手。

View Script 的 ⚙ CONFIG 标签里也有 POST-LOOP 开关和 Process 选择器，但没有 Run at 选项 —— 在那里切换开关，会保留你在这里选好的 Run at。

从另一台设备复制 Script

你可以从备份中复制 Script —— 你自己的备份、别的设备发来的备份，或者内置的示例。点顶部的 ⧉ COPY：

  1. 选择来源 —— 📦 Sample (built-in)、本机上的备份（name (Local) · dd/mm hh:mm），或者用 ＋ Browse a backup file (Local) 打开别人分享给你的文件。在带同步服务器的版本中（且已打开 PRO MODE），还会列出服务器上的备份。点其中一个即可查看它的 Script。
  2. 查看状态 —— 每个 Script 都带一个标记：
    • NEW —— 本机还没有这个 Script；点 Copy 即可添加。
    • HAVE —— 你已经有这个 Script，且 Step 和设置完全一致；不需要复制。
    • DIFF —— 你有同名的 Script，但 Step 或设置不同（例如循环次数不一样）。点 Copy 会用远端版本覆盖你本地的版本。
  3. 确认并复制 —— 点 Copy，在弹窗中确认，DeepTap 就会把该 Script 复制到你的设备上（同名的 Script 会被覆盖）。

Script 会把它需要的东西一起带过来。如果它用到了你还没有的 Process 或 Detector —— 它的 post-loop Process（开启时）、挂在某个 Action 上的 Process、THEN 里的 Run process、WHEN 用的 Detector，或 Click button 用的 Detector —— DeepTap 会在 Copy dependencies too? 里把它们列出来。点 Copy all 会把它们和 Script 一起复制过来；点 Cancel 则什么都不复制。缺少的项目按名称查找。

提示：当你在一台手机上调试好一个 Script、想快速部署到另一台手机时，或者朋友分享给你一个能用的 Script 时，复制功能就很好用。

开始与停止播放

当 Script 里已经有 Step 后，按 ▶ START 就能开始：

  • DeepTap 会把悬浮控制条显示在目标应用之上。
  • 它按顺序执行所有已启用的 Step，如果循环次数大于 1 就回到开头再来一轮。
  • 如果开启了 post-loop，DeepTap 会在每轮循环中运行一次你选定的 Process —— 在这一轮的第一个 Action 之前（Loop start），或在最后一个 Action 之后（Loop end）。
  • 播放期间，控制条上的播放按钮会变成一个红色方块，随时点它都能立即停止。

DeepTap 会在后台持续运行 —— 你可以去用别的应用，或者把手机放进口袋，Script 照常播放。

警告：Script 运行期间，不要卸载 DeepTap，也不要撤销权限（无障碍服务或悬浮窗）。这可能导致手机锁屏或 Script 意外中断。如果需要修改设置，请务必先点 ⏹ Stop。

Detector：识别弹窗和画面

Detector（检测器）教会 DeepTap 识别手机上何时出现了某个特定的弹窗或画面。它的做法是在屏幕的特定 Region 内寻找视觉标志（比如一个"关闭"按钮或某个独特的图标）。一旦认出来，DeepTap 就可以触发相应动作，或者跳到 Script 的下一个 Step。

Detector 的工作方式

每个 Detector 都由三部分组成：

  1. 按钮 —— 你要寻找的视觉标志（比如弹窗的关闭按钮或某个目标按钮）。每个按钮都有一个代号（例如 BTN_CLOSE）和一段说明。
  2. 识别标志规则（Identifier Rule） —— 决定哪些按钮匹配后 Detector 才算"命中"。可选 AND（所有被标记的按钮都要找到）或 OR（找到任意一个被标记的按钮就够了）。
  3. 阈值（Threshold） —— 屏幕上的按钮要跟你截取的 Template 有多相似才算数。默认 90%（0.90）。数值越高匹配越严格。
Template 是跟设备绑定的：当你截取一个视觉标志（从屏幕上裁剪下来）时，DeepTap 会按这台手机的分辨率保存一张 PNG 快照。如果你从另一台设备复制一个 Detector，它的 Template 也会一并复制过来，DeepTap 可以立即开始匹配。

示例 Detector（可编辑的初始数据）

DeepTap 没有任何写死的 Detector。全新安装时它会预置 4 个示例 Detector —— 它们就是普通数据，可以像其他 Detector 一样编辑、复制或删除（📦 Sample 备份里也包含它们）：

  • SIMPLE Popup1 和 SIMPLE Popup2 —— 识别一个弹窗（识别标志为 BTN_POPUP1/BTN_POPUP2，另外还有要点击的动作按钮 BTN_COLLECT）。
  • ADVANCE Popup Close Button —— 识别用来关闭弹窗的 × 按钮，标志为 BTN_CLOSE。
  • ADVANCE Popup Gone —— 识别弹窗已经消失、你已回到它背后那个画面的状态（标志为 BTN_GONE）。

内置的 SIMPLE/ADVANCE Close Popup 系列 Process 用的就是这几个 Detector。你也可以从另一台设备复制示例 Detector 的 Region 和 Template，这样就不用在本机重新裁剪了。

创建或编辑 Detector

打开应用底部的 DETECTORS 标签来管理你的 Detector（最新的排在最上面）：

  1. 点 + NEW 新建一个 Detector，或点已有 Detector 的名字来编辑它。
  2. 填写 Detector 名称并设置阈值 Threshold (%) —— 一般 90 就够用。数值调低（例如 70）更宽容，适合按钮每次长得不太一样的情况；调高（95 以上）则更严格。
  3. 选择识别标志规则：AND 或 OR。
  4. 在 BUTTONS 区域，点 + Add button 逐个添加你要寻找的视觉标志。
    • 填写按钮代号（例如 BTN_CLOSE、BTN_TARGET）。
    • 加一段说明（这个按钮是干什么的？）。
    • 在决定 Detector 是否命中的按钮上勾选 identifier（多个按钮按 AND / OR 规则组合）。没勾选的按钮只是点击目标。至少要勾选一个按钮。
    • 选择它的 match methods（tried in order, tick at least 1）—— 见下表。点任意勾选框旁边的 ? 可以看到简短说明。
  5. 点 SAVE。
要改按钮代号？DeepTap 会自动同步 identifier 勾选 —— 重命名一个已勾选为识别标志的按钮，它仍然保持勾选。

匹配方式：NCC、MASKED、SHAPE

每个按钮最多可以用三种方式来匹配。只有勾选了的方式才会运行，并按这个顺序依次尝试，第一个达到 Detector 阈值的方式胜出。新建的按钮默认只勾选 NCC。

方式比较的是什么适用场景
use NCC (color match)逐个像素把亮度与 Template 比较 —— 形状和颜色都必须一致。大多数按钮。它能区分亮着的按钮和变暗、变灰的按钮。
use MASKED (bright parts)只比较 Template 中的亮色像素（例如白色的 ×），忽略背景。背景会变色，但符号始终比背景亮。
use SHAPE (shape, ignore color)只比较轮廓，忽略颜色。同一个图标会以不同颜色出现（例如广告的 ×，有时是红色背景，有时是蓝色背景）。裁剪时要紧贴按钮内部。
颜色有含义的按钮不要勾选 SHAPE（灰色 = 锁定，绿色 = 可点）—— SHAPE 忽略颜色，两种状态都会匹配上。匹配成功的方式会以 NCC、MASKED 或 SHAPE 的形式显示在实时日志、Detail Log 和 Test Detector 的高亮框里。

裁剪 Template（Region）

保存 Detector 之后，你还必须截取一张视觉 Template，DeepTap 才知道要找什么。这一步在悬浮控制条上完成，就在你要自动化的那个应用之上：

  1. 打开控制条菜单 → List Detector，点该 Detector 的名字。它的面板 Current Detector 会列出这个 Detector 的按钮及各自的 Region（最新的 Region 在最上面）。
  2. 在某个按钮上点 ＋ Add。屏幕中央会出现一个小 Region（15 × 15 像素）：一个标着 NN · BUTTON 的橙色虚线框，下方连着一个调节钮。
  3. 移动方框并调整大小，把你要截取的按钮或标志框住：
    • 拖动调节钮。LOCK 打开时（带 🔒 的绿色调节钮，默认状态），整个方框会跟着移动；LOCK 关闭时（带编号的橙色调节钮），只有调节钮自己移动。
    • 点调节钮，或点 Current Detector 里该 Region 的 #NN，就会打开 Region 面板：用 WIDTH / HEIGHT 滑块（最大 300 像素）和 − / + 调整大小，用 MOVE ±1 的方向箭头每次微调 1 像素。
  4. 点 Crop，对该区域截图并保存为你的 Template（它会显示在 TEMPLATE 下方）。然后点 Save。

Region 面板里还有：眼睛图标（在屏幕上显示或隐藏这个 Region —— 隐藏的 Region 照样参与匹配）、用来标记已完成 Region 的 OK / Not Ready 切换按钮（不影响匹配）、PRIORITY: NORMAL / HIGH（HIGH 的 Region 会先被检查）、◈ TEST 和 ◉ CLICK。改动是即时生效的 —— 点 Cancel 并不会撤销它们。只有裁剪过的 Region 才会用于匹配。

在 Current Detector 里，顶部的几个切换按钮用来筛选列表（Visible、Ready、Priority —— 点一下切换到下一种状态）。每一行 Region 都有 HIGH / norm、Visible / Hidden、OK / Not Ready、Reset（把 Region 移回屏幕中央，大小不变）和 ×（删除）。

现在这张 Template 已经保存在手机上，归属于该 Detector 的这个按钮。播放时 DeepTap 扫描屏幕，会拿这张图去匹配。

一个按钮要多个 Region？你可以为同一个按钮添加多个裁剪区域（当按钮在不同画面上出现在不同位置时很有用）。DeepTap 会先检查 HIGH 优先级的 Region，再按顺序检查其余的，并点击第一个匹配到的。

检查和清理 Region

  • View regions —— 在 DETECTORS 标签里，点某个 Detector 那一行上的图片图标。你会看到每个按钮的每个 Region，以及它裁剪的图片、编号 #NN、OK / Not Ready，还有 no crop、hidden 或 high 之类的标记。这里只能查看，不能修改。
  • ⌫ CLEAN（DETECTORS 标签顶部）—— 扫描所有 Detector，提议删除从未裁剪过的 Region（它们永远不可能匹配）和重复的 Region（同一位置、同一张图）。它会先显示数量并征求你的确认；删除后无法撤销。Current Detector 里的 CLEAN 按钮对当前这一个 Detector 做同样的事。

状态标记说明

从另一台设备复制 Detector 时，选择列表会在每个 Detector 旁显示一个标记：

  • NEW（绿色）—— 本机还没有这个来源 Detector。
  • HAVE（灰色）—— 你已经有同名且配置完全相同（按钮、规则、阈值）的 Detector。
  • DIFF（橙色）—— 你有同名的 Detector，但配置不同（按钮或规则不一样）。

使用你的 Detector

当一个 Detector 已经裁好了 Template，你就可以这样用它：

  • 作为某个 Action 的条件：编辑一个点击或滑动 Action，切到 RULE 标签，打开 ADVANCED，在 WHEN (condition) 里选择你的 Detector。这样只有该 Detector 匹配成功时，这个 Action 才会执行（如果打开了 Invert，则只在它不匹配时执行）。
  • 用在动态 Process 规则里：把该 Detector 用作 WHEN 条件，或作为 ClickButton 动作的目标。
  • 在 Detector 覆盖层里：测试运行过程中实时查看和调整 Region。

理解 DeepTap 中的 Process

DeepTap 里的 Process（流程）是一个小型决策器。它可以作为 Script 的 post-loop Process 每轮循环运行一次，也可以在某个 Action 的规则里运行，或者由另一个 Process 调用。可以把它想成一串"如果发生了这个，就做那个"的规则，DeepTap 按顺序逐条检查，第一条匹配的规则生效，其余的全部跳过。

为什么要用 Process？

Process 用来处理运行过程中冒出来的各种意外情况：

  • 关掉某个动作之后出现的弹窗
  • 处理弹出的提示消息或对话框
  • 决定什么时候停止或重置 Script
  • 根据屏幕上的内容改变 DeepTap 的行为走向

Process 的运作方式：WHEN → THEN → OUTCOME

Process 里的每条规则都有三个部分：

部分 作用 示例
WHEN（条件） DeepTap 对屏幕做的一次检查。检查通过，这条规则就触发。 "如果出现了弹窗的关闭按钮"或"如果电量低于 20%"
THEN（动作） 条件匹配时，DeepTap 依次执行的一个或多个动作 等待 500 毫秒，然后点击关闭按钮
OUTCOME（流程走向） 动作执行完之后 DeepTap 该怎么走 继续循环、重置回开头，或停止 Script

WHEN：条件

DeepTap 会拿条件跟当前屏幕上的内容作比对：

  • Always —— 永远匹配的条件。适合放在 Process 最后作为兜底规则，处理前面都没接住的情况。
  • Detector match —— DeepTap 去找某个指定的 Detector（你教它识别的某个 Region，比如 "popup_close_button"）。可以选择你在 Detector 部分创建的任何一个。
  • Invert —— 打开这个开关可以把条件取反。例如把"如果 popup_close_button 出现"变成"如果它并没有出现"。
  • Battery level —— DeepTap 检查设备电量，当低于或高于你设定的百分比（默认 20%）时触发。
条件是怎么起作用的：一个条件要么匹配、要么不匹配。匹配时，DeepTap 执行 THEN 里的动作，然后按 OUTCOME 走；不匹配时，DeepTap 直接跳过这条规则，去检查下一条。

THEN：动作

条件匹配后，DeepTap 会按顺序一个接一个地执行这些动作：

  • Wait —— 暂停指定的毫秒数（1000 毫秒 = 1 秒）。适合等动画播完再点击。
  • Click button —— 点击 WHEN 条件里那个 Detector 的某个指定按钮。选择"Click button"后，DeepTap 会列出该 Detector 上可用的按钮，你挑一个来点。
  • Send Back —— 按一次或多次设备的返回键。适合关掉对话框。
  • Send Home —— 按 Home 键，回到桌面。
  • Send Recents —— 按 Recents 键（最近任务 / 应用概览）。
  • Scroll —— 按你选择的方向滚动屏幕。
  • Send Text —— 在当前获得焦点的输入框里输入一段文字。
  • Send Enter —— 在当前获得焦点的输入框里按回车（Android 11 及以上）。
  • Capture —— 在本机保存一张截图（可以在 CONFIG → General → SCREENSHOTS → VIEW 里浏览）。
  • Notify Discord —— 向你自己的 Discord webhook 发送一条消息（CONFIG → Advance → DISCORD NOTIFY）。
  • Perform action (caller) —— 执行启动这个 Process 的那个 Action 本身的点击或滑动。在 Action 自己的 RULE 标签里，它叫 Do this action。
  • Lock Screen —— 立即锁屏（Android 9 及以上）。
  • Run Process —— 就地调用另一个 Process，就像嵌套的小脚本。那个 Process 跑完后，控制权回到当前 Process。如果嵌套的 Process 以 Stop 或 Reset 结束，这个结果会直接向上传递、让父 Process 也随之中断。
动作顺序很重要：DeepTap 严格按你列出的顺序执行动作。如果你写"等 2 秒再点击"，它就真的先等再点；把顺序颠倒过来，时序也就变了。

OUTCOME：接下来怎么走

所有动作执行完后，OUTCOME 告诉播放引擎该做什么：

  • Continue —— 立即开始下一轮播放循环。当你已经处理好当前情况、DeepTap 应该继续干正事时用它。
  • Next Step —— 跳到本 Process 的下一个 Step。DeepTap 会重新扫描屏幕，再检查下一个 Step 的条件。
  • Go to Step N —— 跳到指定的某个 Step（可以往前也可以往后）。DeepTap 会重新扫描并检查那个 Step 的条件。做轮询很有用：一个 Step 可以不断跳回自己，直到条件发生变化。
  • Reset —— 让主播放循环从头重新开始。当屏幕发生了较大变化时很有用。
  • Stop —— 结束本次 Script 运行。播放引擎停止并回到空闲状态。
  • Chain → [Process 名称] —— 当前 Process 结束后接着运行另一个 Process。选这个 OUTCOME 时需要指定要运行哪一个。常见用法：一个 Process 做完事之后，串联到 "ADVANCE Close Popup Process"。

创建和编辑 Process

在 Processes 页面：

  1. 点 + New 新建一个 Process，或点已有 Process 的名字来编辑它。
  2. 给这个 Process 起个名字（例如 "Handle Popups"）。
  3. 如果想把这个 Process 挂到某个 Script 上，作为它的 post-loop Process（之后每轮循环运行一次），就打开 Show in post-loop picker；如果它只应该被别的 Process 通过 Chain OUTCOME 或 Run Process 动作调用，就保持关闭。
  4. 设置 Max Duration (minutes) —— 这个 Process 最长允许运行多久。超时后 DeepTap 会中止它并返回 Continue。默认 10 分钟，用来防止无限循环。
  5. 点 + Add Step 添加一条新规则（Step）。
  6. 点某个 Step 展开它，编辑 WHEN、THEN 和 OUTCOME。
  7. 用上下箭头调整 Step 的顺序。
  8. 完成后点 Save。

不匹配的 Step

如果某个 Step 的条件不匹配，DeepTap 会跳过这个 Step 的动作、完全不执行它们，直接看下一个 Step。这样效率很高：只有第一个匹配上的 Step 会运行，其余的全部略过。

内置的示例 Process：SIMPLE 与 ADVANCE Close Popup

DeepTap 预置了两个可编辑的示例 Process，完整演示了 Detector → Process 这一整套机制。它们就是普通数据 —— 可以编辑、复制或删除，📦 Sample 备份里也包含它们。两个都打开了 Show in post-loop picker，因此都可以挂作某个 Script 的 post-loop Process。

SIMPLE Close Popup Process —— 每种弹窗对应一个 Step：WHEN SIMPLE Popup1（或 SIMPLE Popup2）Detector 匹配 → 点它的 BTN_COLLECT 按钮 → Run Process → 交给 ADVANCE Close Popup Process 去关掉随后出现的弹窗。

ADVANCE Close Popup Process —— 一个由六个 Step 组成的循环，专门寻找弹窗的关闭（×）按钮：

  • Step 1–2：ADVANCE Popup Gone Detector 必须匹配两次，这个 Process 才算结束：第一次看到只是"预备"，然后等 3 秒再检查一次；第二次看到后再等 2 秒，然后返回 Continue。
  • Step 3：在还没确认弹窗"已消失"之前，连发 2 次返回键（间隔 200 毫秒），然后重新扫描。
  • Step 4–5：ADVANCE Popup Close Button Detector（那个 ×）—— 每第 3 次看到时，先按一次返回键并重新扫描；如果 × 还在，就点 BTN_CLOSE，等 3 秒后从头再来。
  • Step 6：什么都没找到 —— 等 3 秒后从头再来。
  • 最长运行时间 180 秒 —— 到时间弹窗还没关掉，就运行 ADVANCE Popup Timeout：截一张图、发一条 Discord 通知，然后停止 Script。

全新安装得到的就是这个版本。旧的安装会保留它原来的副本，直到你从 📦 Sample (built-in) 重新复制这个 Process。

把它们当作你自己"先检测、再行动"流程的范本：任何需要在动作之后关掉弹窗的 Process，都可以串联到这个 ADVANCE 关闭流程；也可以复制其中一个再按需改造。

从另一台设备复制 Process

你可以从备份中复制 Process —— 你自己的备份、别的设备发来的文件，或者内置的 📦 Sample（在带同步服务器的版本中，且已打开 PRO MODE 时，也可以从服务器备份复制）：

  1. 在 Processes 列表里点 ⧉ COPY。
  2. 选择你想从中复制 Process 的来源。
  3. DeepTap 会扫描所选 Process 的依赖项 —— 它引用到的 Detector 或子 Process。
  4. 每个 Process 旁边会显示一个状态标记：
    • NEW（绿色）—— 你的设备上还没有这个 Process，DeepTap 会把它复制过来。
    • DIFF（橙色）—— 本地存在同名 Process，但内容不同。DeepTap 会询问是否覆盖。
    • HAVE（灰色）—— 本地已有且完全相同，无需复制。
  5. 点 Copy。如果这个 Process 依赖你还没有的 Detector 或子 Process，DeepTap 会连带提议一并复制过来。这通常比手动重建快得多。

用 Run Process 实现嵌套

Process 可以通过 Run Process 动作调用别的 Process。系统设有嵌套深度上限以防止无限递归，而且每个 Process 每次被调用时都有自己的 Max Duration 限制。当嵌套的 Process 返回 Stop 或 Reset 时，这个结果会立刻向上传递给父 Process。

把 Process 用作 Post-Loop 钩子

如果一个 Process 打开了 Show in post-loop picker，你就可以把它挂到某个 Script 上：HOME → 该 Script 的 ⋮ → Edit post-loop（见 Script 一节中的 Post-Loop）。之后它会每轮循环运行一次 —— 在每轮开始时（默认）或结束时。而它的 OUTCOME 决定循环是继续、重置还是停止。

整理你的 Process：尽量保持简单。3–5 个 Step 的 Process 比 20 个 Step 的好调试得多。如果发现自己嵌套了很多层，考虑把复杂逻辑拆成几个小 Process，再用串联把它们连起来。

默认的最长运行时间

新建 Process 的默认最长运行时间是 10 分钟（600,000 毫秒）。担心死循环可以调小，Process 确实需要跑更久也可以调大。设为 0 表示关闭超时限制（不限时）。

AI 助手 —— 用 ChatGPT 搭建 Process

PROCESSES 页面上有一个悬浮的 AI 按钮，点开就是 AI 助手 —— 它让 AI 聊天机器人（例如 ChatGPT）替你设计或修改 Process 和 Detector。你只需用任何语言的大白话描述需求，再把 AI 的回答粘贴回 DeepTap：

  1. COPY FOR AI —— 把一段指令提示词，连同你当前的 Process 和 Detector 结构一起复制到剪贴板。
  2. 粘贴到 ChatGPT —— 把剪贴板内容粘进任意 AI 聊天窗口，并描述你想要的自动化效果。
  3. 把回答粘回来 + CHECK —— DeepTap 会校验 id、引用关系和结构，然后列出将要发生哪些改动。
  4. APPLY —— DeepTap 先保存一份安全备份，再按 id 合并这些改动。

🐞 DEBUG BUNDLE FOR AI（在 COPY FOR AI 下方）用于出问题的时候：它把所有内容一次性打包 —— Script、Process、Detector、Region 图片和运行日志 —— 让 AI 能一步步复现发生了什么。约 512 KB 以内会复制到剪贴板；更大的数据包会以文件形式打开分享面板。运行日志来自 DETAIL LOG（默认开启）；如果它是关闭的，请先打开，把问题复现一次，然后再导出。

由于是按 id 合并，已有条目会就地更新、新条目会被添加 —— 其他内容完全不受影响。新创建的 Detector 还没有任何 Region：运行之前，请在 Current Detector 里逐个打开它们，点 ＋ Add，把方框放到真正的按钮上，再 Crop 一张 Template。如果 APPLY 之后发现哪里不对，恢复那份安全备份即可。

时间与性能：让 DeepTap 更快（或更有耐心）

DeepTap 在 CONFIG → Advance → TIMING 里有五项时间设置。这一区域默认是折叠的 —— 点 SHOW 展开（每次打开 Config 它都会重新折叠）。它们控制一次点击按住多久、DeepTap 多久扫描一次屏幕、点击前等多久，以及每次扫描占用多少内存。每个输入框都有一个 ?，点开可以看到简短说明。

五项设置

设置项 作用 默认值 取值范围
CLICK HOLD Process 或 Action 规则（Click button）发出的点击，以及 Region 面板里的 ◉ CLICK，每次点击时手指按住多久。Script 自己的点击则用它们各自的 TIME HOLD。 50 ms 10–2000 ms
SCAN INTERVAL 两次截屏之间的最短间隔（下限 333ms，由 Android 规定） 500 ms 333–5000 ms
CLICK DELAY 检测到按钮之后、真正点击之前的等待时间 500 ms 0–5000 ms
RE-SCAN AFTER 一张截屏最多可以"过期"多久，超过就重新截取（0 = 关闭） 500 ms 0 或 500–60000 ms
MATCH RESOLUTION 匹配前先缩小截屏以节省内存（0 = 原始分辨率，不缩小） 0（关闭 —— 原始分辨率） 0 或 480–4000 px

为什么这些设置很重要

SCAN INTERVAL 的下限是 Android 无障碍层硬性规定的。如果两次截屏的间隔短于 333 毫秒 —— 比如父 Process 内部又运行了子 Process，或者 DeepTap 要对同一画面复查一次 —— 第二次截屏会静默失败、什么也返回不了。在弄清原因之前，这个问题曾被误认为是旧的 Slow-Log 开关（现已由 DETAIL LOG 取代）导致的：它那约 1 秒的暂停碰巧把两次截屏拉开了足够的间隔，于是就"能用了"。现在 SCAN INTERVAL 会自动解决这个问题。不要把它设到 333 毫秒以下，反正 Android 也不会理会。

CLICK DELAY 是在 DeepTap 检测到按钮和真正点下去之间插入的一段停顿。它是必要的，因为：

  • 刚出现的按钮可能还在播放入场动画，此时还不能响应点击。
  • 紧跟在截屏之后立刻发出的点击，可能会被系统取消掉。

设为 0 即可关闭。设备快的话可以降到 100–200 毫秒；设备慢的话调到 1000 毫秒甚至更高。

CLICK HOLD 主要对模拟器有影响：如果点击太短，有些模拟器只会让按钮高亮，却不算作一次点击。如果 Process 发出的点击能让按钮亮起来、但什么也没发生，就把它调高（例如 100–200 毫秒）。

RE-SCAN AFTER 解决的是一个不太起眼的问题：如果某个 Process 在单个 Step 里耗时很久（比如一次很长的 Wait，或者一个不停轮询的子 Process），那么开头拍下的那张截屏就"过期"了。等它真要点击时，屏幕可能已经变了。这时 DeepTap 会重新截屏再检查一次；如果按钮移位或消失了，它会安全地跳过这次点击，而不是对着幻影乱点。设为 0 则关闭该功能，始终使用最初那张截屏。最小值 500 毫秒（再低 Android 也会限流）。

MATCH RESOLUTION 会在把截屏与已保存的图样比对之前先把它缩小。现在手机上一张全屏截图约 13 MB，而且整个扫描过程都要占着内存。在内存较小的设备上，这会造成卡顿和垃圾回收引起的假死。把最长边限制到比如 1600 像素后，DeepTap 会立刻丢掉原分辨率的那份，只保留缩小版。由于 DeepTap 本来就会把每个 Region 缩放到 64×64 再比对，适度缩小几乎不影响准确度。默认值是 0 —— 原始分辨率、不缩小；只有当低内存设备出现卡顿或假死时，才去设一个像素上限（例如 1600）。只有超过该上限的画面才会被缩小，尺寸更小的画面保持原样。

什么时候该调这些设置：
  • DeepTap 漏掉按钮，或者嵌套的 Process 一直不运行：把 SCAN INTERVAL 调到 400–600 毫秒或更高（有些 Android 版本要求的间隔比 333 毫秒更长）。同时确认 MATCH RESOLUTION 是 0（原始分辨率），这样小按钮才能保留细节。
  • 点击没生效，或者点错了位置：把 CLICK DELAY 调到 800–1500 毫秒，让按钮稳定下来之后 DeepTap 再点。
  • 按钮亮了一下，但点击没有任何效果（模拟器上常见）：把 CLICK HOLD 调到 100–200 毫秒。
  • 长时间运行 Script 时设备发烫或变慢：给 MATCH RESOLUTION 设一个上限来节省内存 —— 先试 1600，再试 1200；不要低于 480，否则小图标会糊得太厉害。
  • DeepTap 在动画播到一半时拍到画面、点错了元素：把 RE-SCAN AFTER 调到 5000–10000 毫秒，让过期的截屏更早触发重新截取。

系统状态条

打开 SHOW SYSTEM STATS（CONFIG → Advance → LOG），就能在 DeepTap 运行时看到内存和电量指示。它能实时告诉你某项设置的改动（尤其是 MATCH RESOLUTION）有没有真的降低内存占用。留意可用内存的下降或耗电的骤增 —— 这些都是该给 MATCH RESOLUTION 设上限（或把现有上限再调低）的信号。

重要：时间设置在你按下 Config 底部的 SAVE 时应用（随后 Config 会关闭）。改动立即生效，不需要重启 DeepTap 或应用。

截图与日志

SCREENSHOTS 在 CONFIG 的 General 标签里：截图只保存在本机 —— 点 VIEW 可以浏览已保存的图。Advance 标签里有 LOG 区域 —— LIVE LOG（默认关闭：在控制条的日志条上显示 Process 和 Detector 的消息）、DETAIL LOG（默认开启：易读的逐步引擎日志，保留最新的 10,000 个字符；从控制条菜单 → Log detail 打开，可以 COPY 和 CLEAR）和 SHOW SYSTEM STATS —— 另外还有 DISCORD NOTIFY。

保存并测试

调整完任何一项时间设置之后：

  1. 点 Config 底部的 Save。
  2. 关闭 Config，跑一个测试用的 Script 或做一次截取。
  3. 观察日志，或打开 SHOW SYSTEM STATS，看看改动有没有效果。
  4. 如果没效果，再调再试 —— 反复微调不会有任何副作用。

备份与跨设备同步

DeepTap 可以备份你的自动化配置，并在你的手机、平板和模拟器之间转移。本节讲解备份的原理、"复制单个项目"和"恢复全部内容"之间的重要区别，以及 —— 在带同步服务器的版本中 —— 如何让所有设备上的 Detector、Process 和 Script 保持一致。

你能用到哪些功能，取决于你的版本。备份到本机（同时在 Download 文件夹里存一个文件）、Share、⧉ COPY，以及用 ↺ RESTORE 从本机备份恢复，在所有版本里都能用。凡是用到服务器的功能 —— 备份到服务器、复制或恢复服务器上的备份、Merge、⟳ SYNC ALL、↑ UPLOAD / ↓ DOWNLOAD、CHECK 以及网页管理后台 —— 都需要同步服务器，并且要打开 PRO MODE（CONFIG → General）。Google Play 版本没有服务器，所以这些按钮在那里根本不会出现。

备份的原理

打开 CONFIG → General → BACKUP，点 ⤴ BACKUP。备份进行时，按钮上会显示转圈动画和百分比。备份内容包括：

  • 所有 Script（你录制的点击/滑动动作序列）
  • 所有 Detector（DeepTap 学会在屏幕上识别的图样）
  • 所有 Process（你的自动化规则和逻辑）
  • 按钮的 Region（DeepTap 点击的精确屏幕位置）
  • Template 图片（DeepTap 用来找按钮的裁剪截图）

备份保存到哪里，由 BACKUP DESTINATION 决定：

  • LOCAL —— 保存在应用里，同时在 Download 文件夹里存一个文件 DeepTap_USERNAME_date.txt（同名的旧文件会被替换）。这是 Google Play 版本里唯一的选项，PRO MODE 关闭时也只能选它。
  • SERVER（带同步服务器的版本，且已打开 PRO MODE）—— 上传到你的账户。所有使用同一个 USERNAME 的设备共用这一份服务器备份：每次备份到服务器都会替换它。

Share 会保存一份带 Template 的新备份，并打开 Android 的分享面板 —— 通过 Gmail、Zalo、Messenger 或云盘发到另一台设备，然后在那台设备上用 ⧉ COPY → ＋ Browse a backup file (Local) 把需要的项目导入进来。

设置 Username 和 Backup password

这两项都在 CONFIG → General → BACKUP 里。服务器需要这两项 —— 少了它们，服务器备份、恢复和同步都会被拒绝。本机备份则两项都不需要。

  • USERNAME —— 你的账户，也是 Merge、Upload 和 Download 所经过的同步库（sync hub）。长度 3–64 个字符：字母、数字以及 . _ + -。第一次用到服务器的操作就会注册它，所以一旦打错字，就会悄悄创建一个新的空账户。
  • BACKUP PASSWORD —— 至少 6 个字符，由服务器校验，防止另一台用同样用户名的设备覆盖你的数据。它不是登录密码。

在你所有设备上都用同一个 USERNAME 和密码 —— 手机之所以能恢复平板备份的内容，Merge、Upload 和 Download 之所以能在设备之间工作，靠的就是它。全新安装时，USERNAME 会预先填好你的手机型号加一个数字（例如 2412DPC0AG-6401），密码则是空的：第一次备份到服务器之前，请把用户名改成你认得出的名字。⤴ BACKUP 和 ↺ RESTORE 使用的是你当前填写的内容，即使还没按 SAVE 也一样。

某台设备看不到你的备份或已同步的项目？检查它的 USERNAME 和密码是否与你其他设备上的一致 —— USERNAME 不同，就是不同的账户。

Copy 与 Restore —— 关键区别

DeepTap 提供了两种截然不同的方式来从备份中获取自动化配置 —— 你自己的备份、别的设备发来的备份，或者内置的 📦 Sample。你必须弄清楚该用哪一种：

对比项 ⧉ COPY（安全） ↺ RESTORE（破坏性）
复制什么 你指定的某一个 Detector、Process 或 Script（如果你确认，还会带上它需要的东西） 备份里的全部内容，一次性搬过来
本机原有内容 其他自动化配置原封不动 🔴 备份里没有的东西全部被抹掉
Detector 只覆盖同名的那一个 🔴 彻底替换你所有的 Detector
Process 只覆盖同名的那一个 🔴 彻底替换你所有的 Process
Script 只覆盖同名的那一个 🔴 彻底替换你所有的 Script
Region（按钮） 随 Detector 一起过来，连同它们的 Template 🔴 完全替换所有 Region —— 备份里没有的 Region 会被删除，连同它的裁剪图片
关键提醒：Restore 是破坏性操作。如果你恢复了一周前的备份，这一周里新增或修改的一切都会消失。恢复之前，务必先备份这台设备 —— 备份到 LOCAL（或用 Share）：如果现在备份到服务器，就会把你正想恢复的那份服务器备份替换掉。

从备份复制（非破坏性）

用 ⧉ COPY 可以安全地取来单个自动化配置，完全不影响你自己的成果。它在每个列表的顶部：HOME（Script）、PROCESSES 和 DETECTORS。

可以从哪里复制：📦 Sample (built-in)；本机上的备份（name (Local) · dd/mm hh:mm）；用 ＋ Browse a backup file (Local) 打开别人分享给你的文件；另外，在带同步服务器的版本中（且已打开 PRO MODE），还有你账户的服务器备份以及别人共享给你的备份。

会复制哪些内容：

  • 复制 Detector 时：识别图样、它的所有按钮 Region，以及对应的 Template 图片
  • 复制 Process 时：全部自动化规则 —— 如果你确认，还会带上它需要的 Detector 和子 Process
  • 复制 Script 时：录制好的点击/滑动序列 —— 如果你确认，还会带上它用到的 Process 和 Detector

冲突是怎么处理的：

  • 本机上同名的项目会被替换 —— 只替换那一个
  • 其他所有自动化配置保持原样
  • Region 保持原来的像素位置；在分辨率不同的屏幕上，你可能需要移动它们并重新裁剪（见下文）

分步操作（Script、Process 和 Detector 都一样）：

  1. 点列表顶部的 ⧉ COPY
  2. 选择来源
  3. 点你想要的项目 —— 它的标记会显示 NEW、HAVE 或 DIFF
  4. 如果它用到了你还没有的 Detector 或 Process，DeepTap 会在 Copy dependencies too? 里把它们列出来 —— 点 Copy all 一起复制过来，或点 Cancel 什么都不复制
  5. 确认复制 —— 完成
级联复制：Process 和 Script 会把它们依赖的项目（按名称查找）一并带过来，这样就不会出现指向本机不存在项目的引用。Detector 没有需要带上的依赖。

Restore 完整备份（破坏性 —— 请先备份！）

只有当你想用一份完整备份彻底替换本机的自动化配置时，才使用 ↺ RESTORE（CONFIG → General → BACKUP）。典型场景是：

  • 你卸载后重装了 DeepTap，想把原来的配置找回来
  • 你要把整套配置从一台设备克隆到另一台（并且不在乎目标设备上原有的内容）

Restore 会做什么：

  • 用备份里的版本替换所有 Detector、Process 和 Script
  • 用备份里的 Region 完全替换 —— 你本地新增的 Region 会被删除，连同裁剪图片
  • 抹掉本机上一切不在备份里的内容

执行 Restore 之前：

  1. 把 BACKUP DESTINATION 设为 LOCAL，点 ⤴ BACKUP，保存这台设备的自动化配置
  2. 确认显示的是 Backed up to Local ✓
  3. 现在就可以放心点 ↺ RESTORE，在 Restore from… 里选择那份备份了 —— 万一出问题，再恢复你的本机备份即可

在你的设备之间同步

在带同步服务器的版本中（且已打开 PRO MODE），你的 USERNAME 对应的账户就是一个同步库（sync hub）：所有使用同一个 USERNAME 和密码的设备，都可以把项目逐个发送到这里，或从这里逐个取回，而不必恢复全部内容。

方式传输的内容匹配依据效果位置
Backup / Restore全部内容—Restore 会替换全部内容CONFIG → BACKUP
⧉ COPY从备份中取一个 Detector、Process 或 Script名称替换同名项目；可以带上它需要的东西各列表的顶部
Merge / ⟳ SYNC ALLDetector，连同它们的 Region、图片、OK 和 Visible 状态Id + 版本合并 —— 每一部分都以较新的版本为准DETECTORS 标签、List Detector、Current Detector
↑ UPLOAD / ↓ DOWNLOAD（以及 ALL 按钮）Process 和 ScriptId替换另一端的副本 —— 不合并PROCESSES 标签、HOME
删除操作不会同步。如果你在一台设备上删除了某个 Detector、Process 或 Script，而同步库里还有它，⟳ SYNC ALL 或 ↓ DOWNLOAD ALL 会把它又带回来。

Merge —— 单个 Detector。在 DETECTORS 标签里，点某个 Detector 那一行上的 Merge（悬浮的 List Detector 里 Detector 名字下方，以及 Current Detector 的标题栏里也有这个按钮）。DeepTap 会把这个 Detector 与同步库合并，然后上传合并结果：

  • Detector 设置 —— 名称、按钮（连同它们的 identifier 勾选和匹配方式勾选）、阈值、规则：以较新的版本为准。
  • Region 按 id 匹配：以较新的版本为准，连同它的图片。只有同步库里有的 Region 会被添加 —— 除非这台设备在上次 Merge 之后删除了它。只有这台设备上有的 Region 会被保留 —— 除非另一台设备删除了它。
  • OK / Not Ready（Detector、按钮、Region）以及 Region 和按钮的 Visible / Hidden：以最近一次改动为准。
  • 每台设备各自保存、从不同步的：屏幕上显示哪个 Detector、LOCK 状态以及调节钮的位置。

只有在你保存时版本才会变化：Region 面板里的 Save（先 Crop 再 Save）、Current Detector 里的 OK / HIGH 按钮、显示/隐藏开关、OK 开关，以及 Detector 编辑器里的 SAVE。拖动、微调或改变大小但没有 Save，这些改动只留在这台设备上，可能会被同步库里更新的副本替换。合并结果的提示类似 ✓ Merged "name": +2 new · 1 updated · 0 removed。

⟳ SYNC ALL —— 所有 Detector。在 DETECTORS 标签里，⟳ SYNC ALL 会先下载同步库里有、而这台设备上没有的 Detector（连同它们的 Region 和图片），然后把这里的每个 Detector 逐个合并，并显示一个进度窗口。新设备点一下就能把所有内容拉下来。如果 USERNAME 或密码不对，或者没有网络，它会立即停止；单个 Detector 出错时会在最后列出来，其他的照常继续。

↑ UPLOAD / ↓ DOWNLOAD —— 单个 Process 或 Script。这两个按钮在 PROCESSES 标签的每一行上，以及 HOME 的每张 Script 卡片上。↑ UPLOAD 用这台设备上的副本替换同步库里的副本；↓ DOWNLOAD 用同步库里的副本替换这台设备上的副本（同步库里没有时会被拒绝）。项目按 id 匹配，而不是按名称。确认对话框会显示同步库里的副本最后一次是什么时候、由哪个账户修改的。一个项目需要的东西会随它一起传输：另一端缺少的 Detector 会先合并，缺少的子 Process 会一并复制；另一端已经有的则保持原样，即使内容不同 —— 那些请单独上传或合并。Script 会带上它的 post-loop Process、它的 Action 用到的 Process 和 Run process 目标，以及它的 Action 用到的 Detector。

版本、“+”和 CHECK。每个 Script、Process 和 Detector 的名字后面都会显示它的版本，例如 v30/09 21:05 —— 也就是它最近一次 Upload / Download（Script、Process）或 Merge / Sync all（Detector）时的服务器时间 —— 或者显示 no version yet。版本后面的 + 表示这台设备在那之后改动过它：对 Script 和 Process 来说，是内容与同步时不一样了（把改动原样撤销，+ 就会消失）；对 Detector 来说，是上次 Merge 之后保存过改动。CHECK 会询问同步库，并在后面加上 same version as hub、hub: v… · account（另一台设备同步了不同的版本）或 not in hub。切换标签后，这些结果就会清除。没有版本的 Detector 需要做一次 ⟳ SYNC ALL。

↑ UPLOAD ALL · ↓ DOWNLOAD ALL · CHECK ALL。HOME 和 PROCESSES 列表上方的这一栏，会对这台设备上的每个项目执行 ↑ UPLOAD，或对同步库里的每个项目执行 ↓ DOWNLOAD（会添加这台设备上没有的项目；只在这台设备上的项目保持不变），逐个进行，并显示一个进度窗口。在 DETECTORS 标签里，这一栏是 ⟳ SYNC ALL · CHECK ALL。

ALL 类按钮不会比较版本。↑ UPLOAD ALL 会覆盖另一台设备刚上传的较新副本；↓ DOWNLOAD ALL 会覆盖你本地标有 + 的改动。请先按 CHECK ALL，看看哪些不一样。

Template 与屏幕分辨率

按钮 Template（DeepTap 用来找到并点击按钮的裁剪截图）跟设备的屏幕分辨率绑定。从另一台设备复制或合并 Detector 时：

  • 分辨率相同：Template 会完美复制过来，立即可用
  • 分辨率不同：Region 保持原来的像素位置，Template 也保持原来的尺寸，因此可能匹配不上 —— 请在这台设备上移动 Region 并重新裁剪

这也是为什么屏幕尺寸完全相同的设备（比如同一款模拟器或同一型号的手机）之间最适合共享。

访问网页管理后台

在带同步服务器的版本中，备份也可以通过网页管理后台查看和管理，由运行服务器的人保管。后台有登录保护，地址不再需要你在 app 里填写。在那里可以：

  • 查看所有设备的备份及其时间戳
  • 预览各个 Detector、Process 和 Script
  • 在把配置加载到另一台设备之前先做编辑

几种常见用法

用法一：一个账户，多台设备

在每台设备上都用同一个 USERNAME 和密码。在任意一台上改进了某个自动化配置之后，对 Detector 点 Merge，对 Process 或 Script 点 ↑ UPLOAD。在其他设备上先按 CHECK ALL 看看哪些有变化，然后用 ⟳ SYNC ALL（Detector）和 ↓ DOWNLOAD / ↓ DOWNLOAD ALL（Process、Script）。

用法二：新设备或重置过的设备

  1. 填入与其他设备相同的 USERNAME 和 BACKUP PASSWORD
  2. 要么点 ↺ RESTORE，选择你账户的备份（这会替换这台设备上的全部内容）……
  3. ……要么保留现有内容，只拉取已同步的项目：在 DETECTORS 里点 ⟳ SYNC ALL，再在 PROCESSES 和 HOME 里点 ↓ DOWNLOAD ALL

用法三：测试新的自动化

你想试一个新的 Process，又不想拿主力配置冒险。那就用第二台设备（或模拟器）：

  1. 用 ⧉ COPY 只复制你需要的那几个 Detector —— 例如从你主力设备分享出来的备份文件里复制
  2. 在这里安全地搭建并测试新的 Process
  3. 调通之后，再把它带回主力设备 —— 用 Share 加 ⧉ COPY，或者在这台上 ↑ UPLOAD、在那台上 ↓ DOWNLOAD
记住：分享零散的小部件用 ⧉ COPY，整体替换才用 Restore；Merge、Upload 和 Download 则让同样的项目在你的各台设备之间保持同步。拿不准的时候，先备份。
